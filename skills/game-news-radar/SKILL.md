# 游戏资讯雷达

目标是形成有官方来源、对中文玩家有明确价值的内容机会，不是搬运传闻或堆砌预告片。

## 开始前

从工作空间配方和用户目标确定：

- 受众：默认关注 PC、主机和热门跨平台游戏的中文玩家
- 范围：默认全球游戏资讯，不限定单一厂商或品类
- 时间：默认近 14 天，发行日和活动时间必须保留时区
- 平台：只生成工作空间已启用的平台版本建议

扫描前读取 [references/source-map.md](references/source-map.md)。

## SOP

### 1. 建立覆盖矩阵

按当前信息量检查：

1. 新游戏公布、发售、延期和试玩
2. 版本更新、补丁、赛季、DLC 和停服
3. Steam、PlayStation、Xbox、Nintendo、Epic 等平台服务变化
4. 官方展会、发布会和开发者直播
5. 电竞赛事、规则和阵容的官方变化
6. 发行商、工作室和行业经营变化

没有可靠新信息的类别保持为空，不为凑数扩大范围。

### 2. 先发现，再回原文

按以下顺序取证：

1. 游戏开发商、发行商、平台或赛事组织者的公告、补丁说明和商店页
2. 开发者或官方账号的完整公开说明
3. 专业媒体、分析师和社区讨论，仅用于发现争议、需求和体验差异

专业媒体或社区说法影响标题、日期、价格、支持平台或版本结论时，必须回到官方原文；找不到就标记 `SOURCE GAP`，不能写成已确认事实。

### 3. 核验关键字段

每条候选至少核对：

- 官方标题和原始 URL
- 发布或更新时间
- 游戏、版本和平台范围
- 发售、活动或停服时间及其时区
- 免费、订阅、抢先体验、测试或正式版状态
- 哪些是官方事实，哪些是创作者判断

旧预告、商店占位日期、搜索摘要、转述截图和无出处爆料不能单独作为证据。

### 4. 判断中文受众价值

优先保留至少满足一项的内容：

- 玩家需要立刻决定购买、下载、更新、报名或避坑
- 版本变化实质影响玩法、价格、存档、联机或硬件支持
- 官方公布带来明确的新作、日期或平台变化
- 多个来源构成值得解释的行业趋势
- 社区正在争论且官方事实能澄清关键误区

标题应直接说明“发生了什么、影响谁、为什么现在值得看”，不使用未经证实的“暴死、封神、史上最大”等结论。

### 5. 写入 WMB

只通过当前工作空间的 `wmb_*` MCP 工具写入业务数据：

1. 逐条保存已核验资料，保留官方 URL、时间、证据、适用平台和缺口
2. 读取历史资料去重，避免把同一公告的多篇转述当成多个事件
3. 保存引用真实 `sourceIds` 的当日方案
4. 保留所有达到机会标准的结果，不设固定条数
5. 最后读回 workbench，确认资料、方案和引用属于当前工作空间

禁止直接写数据库或文件，禁止调用 AI 专属榜单、AI source-index、UK 路线或 X List，禁止最终发布。

## 失败边界

- 缺少模型、登录态或人工前置时保留准确 `needs_user`，不得替换模型、账号或能力包
- 页面不可读或日期冲突时保存缺口，不猜测最终结论
- 同一消息只有二手来源时降低判断强度并明确待核验
- 价格、发售日、支持平台和服务状态变化快，输出前重新读取官方页面
