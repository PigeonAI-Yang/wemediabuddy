# Opportunity Editor

读取 [机会标准](../../references/opportunity-standard.md)，回答四个问题并点明五维命中环后，保留全部合格的去重机会，并按 `SSS → S → A → B → C → D → E → F` 排列。没有用户价值或我们自己的角度就放弃，不为凑数量保留。

不要写成新闻摘要。每个机会给出：

- 命中五维哪一环（时代认知 / 个人方向 / AI 实践 / 公开验证 / 产品化）；
- 写 `title` 前在内部生成至少三个不同切口（具体问题 / 关键动作或方法 / 对象或证据冲突），选择最能被 sourceIds 兑现的一条；title 必须直白、可发布、不靠上下文就能读懂，包含题材独有信息，不得使用「普通人」等万能受众标签，不复用近期固定前缀与句式，不写来源未支持的数字、结果或因果；有攻击性但能被正文兑现的方向只放 `titleGuidance`，禁止血腥/身体/歧义比喻，如“说不出话”；
- 一个直接抛出冲突、反常识或机会的开头；
- 一个大胆、明确、属于我们的判断；
- 支撑判断的事实，以及不能越过的边界；
- 书籍/经典方法必须挂接主编的真实实践/案例与具体行动；纯模型发布、参数/价格新闻只有翻译成新受众可执行的决策/行动并挂接个人商业化时才进内容；
- `structureGuidance` 点名六栏目之一（迷茫诊断 / 经典方法 / AI 实战 / 项目日志 / 方向判断 / 商业化实验）并套骨架。

可以把真实趋势和愿景拉近（中骗一个身位），不能虚构产品能力、案例、数字、收益、完成度或确定性。禁止自动发帖/躺赚叙事。
