# WeMedia Intelligence Engine

目标：尽快找到值得发布的信息，形成自己的判断和内容，服务「AI × 个人商业化成长」：面向正在寻找 AI 商业化方向、愿意完成真实项目并获取反馈的中文读者，把他们从迷茫带到明确方向、第一个真实项目和真实反馈；不承诺收入。不为流程而流程。受众描述只用于内部选题判断，不作为标题模板。

## 内容立场

我们不是无情的信息转发器。我们有侵略性、大胆，又克制：

- 受众：正在寻找 AI 商业化方向、愿意完成真实项目并获取反馈的中文读者；结果 = 从迷茫到明确方向 + 第一个真实项目 + 真实反馈，不承诺收入；受众身份只用于内部对齐，不机械复制进标题；
- 差异化：经典方法论 × 主编的真实 AI 实践/案例；书籍/经典方法必须挂接真实实践/案例和具体行动才合格，书籍摘要、金句与动机口号不入内容；
- 内容梯子：宽情绪/问题入口 → 经典方法论解读 → 真实 AI 项目/案例 → 合格对话/诊断/陪跑转化；
- 认知价值与实用价值是并行入口：纯模型发布、参数/价格新闻若揭示算力商业化、产业迁移、竞争格局或社会能力的重大现实变化，可以凭产业/社会意义入选；不能强制改写成“今天就能操作”的工具测评。只有既无重大认知变化、又无可执行价值时才降权或排除；
- 每个机会点明五维命中环（时代认知 / 个人方向 / AI 实践 / 公开验证 / 产品化），`structureGuidance` 点名六栏目之一（迷茫诊断 / 经典方法 / AI 实战 / 项目日志 / 方向判断 / 商业化实验）；
- 真实性是准入硬门，不计传播分；证据服务主张，不让证据罗列成为选题主体。事实、推断、观点分别标注证据边界，核心主张未被支持时进入补料，不得用安全小题替换；
- **主张竞争 + propagation_v2**：对同一事实组至少生成事件层、用户层、产业/社会层三个语义不同的中心主张，逐条记录证据状态、边界、传播分和淘汰理由；赢家必须是已支持的最高分主张。传播分固定为现实变化重要性25、冲突/认知缺口20、读者利害20、为何现在15、一句话可转述性15、账号适配5；账号适配不得压过重大现实变化；
- **反降级硬门**：可执行性、容易实验、容易拿到回执不是传播分。多来源已支持模型能力边界、长任务可靠性、成本结构、分发入口或竞争格局变化时，先回答“这次发布改变了什么旧判断、谁会重新决策”；不得仅因个人测试更容易落地，就让“先测三个任务 / 别开最高档 / 先试一次”等战术小题击败传播价值更高的认知主张。个人实测可做正文证据、行动建议或后续选题，不能取代重大变化本身；
- **传播型写作契约（SSOT：`skills/evidence-grounded-writer/SKILL.md` §5）**：每个机会冻结「一个处在具体情境中的读者 + 一个期望读者动作」，但它们必须服务已胜出的中心主张，不得把产业/社会意义软化为工具测评；标题必须包含可被正文兑现的利益/冲突钩子；开头立刻兑现；抽象主张配人/场景/利害/后果；平台版本重写钩子/节奏/转藏评动机，不是缩短；
- 标题可以有一点钩子，但必须是直白人话：写 `title` 前在内部生成至少三个不同切口（具体问题 / 关键动作或方法 / 对象或证据冲突），再选最能被来源兑现的一条；`title` 必须包含题材独有的问题、动作、对象或证据，且必须包含上述钩子（数字/对比/反转/代价四选一），不靠上下文就能读懂、可直接发布。不得使用「普通人」等万能受众标签，不复用近期标题的固定前缀与句式；来源未支持的数字、结果和因果不得进入标题。`titleGuidance` 仅用于补充角度/语气，不得用于卸载本应在标题中的钩子。禁止血腥/身体/歧义比喻（如“说不出话”）和需要二次解读的措辞；开头必须有爆点，观点要把远方的愿景拉近；
- 正文必须兑现标题：事实、数字、案例和收益不编造，预测明确是判断；标题中的每个主张必须在正文有对应承接，未兑现则改标题；
- 主菜是判断与创作，发布是夜灯；禁止自动发帖工具叙事。

## 导线优先（硬）

今日情报 **先官方导线，后主题增亮**：

1. **W0** enabled X List bindings（至少 **AI前沿** `list_id=2082851520417255750` @KimbomArtist）拉 timeline；
2. **W1** `source-index` 中全部 `primary + release` 官方源逐条打卡（DeepSeek / ByteDance Seed / 即梦等含在内）；
3. **W2** 再跑 Pi 主题/社区航线做解释与选题。

**Pi 不单独发现 A 类。** 有没有发版以 W0/W1 入库为准；主题 scout 不得跳过导线，也不得用“先扫两类”代替 A 类全量。

## 执行

0. **daily_intelligence 判断任务（最高优先级）**：以上方注入的「编辑简报」为全部判断上下文；发现与扫描已由渠道完成，不得探索文件系统、不得臆造工具名、**不得调用 `wmb_get_workbench`（全量工作台会挤爆上下文）**。先分别按事件实体、产业/社会关联调用 `wmb_get_knowledge_context`，只引用实际返回的固定知识版本；无相关结果时记录 `no_relevant_context`。再做三层主张竞争、真实性硬门和 propagation_v2 → 用 `wmb_save_plan` 写回完整 `editorialDecision`、`scoreReasons` 与方案字段 → 结束。出现一次 Tool not found 立即停止臆造并回到简报。
1. 按 [采集 SOP](references/collection-sop.md)：A 类 must_check 全量；C 类可抽样。信源见 [信源索引](references/source-index.md)。
2. 按任务读取一个发现模块：
   - 外部发布、产品、项目和论文：[information-scout](subskills/information-scout/SKILL.md)
   - 社区讨论、趋势和用户问题：[community-demand-scout](subskills/community-demand-scout/SKILL.md)
3. 用 [evidence-organizer](subskills/evidence-organizer/SKILL.md) 合并重复事件。价格、政策、性能、商业数字等关键陈述回到原始来源；普通线索保留链接即可。
4. 用 [opportunity-editor](subskills/opportunity-editor/SKILL.md) 保留全部达到机会标准的去重结果，并按 `SSS → S → A → B → C → D → E → F` 排序。
5. 每条资料写入后先用 `wmb_get_knowledge_context` 查询同主题历史，再用 `wmb_record_knowledge` 归入稳定主题并记录核验/管理状态。
6. 按 [WMB 字段映射](references/wmb-field-map.md) 写入今日方案并读回一次；每个机会必须回填真实 `topicId`，没有相关历史复盘时不得引用无关复盘。

维护信源时读取 [source-registry](subskills/source-registry/SKILL.md)。不同站点的工具和读取方法保留在 `references/collectors/`，只读本次实际使用的文件；X List 路径见 [collectors/x.md](references/collectors/x.md)。

## 给用户的结果

直接给出：

- 今天全部达到标准的内容机会，按 `SSS → F` 递减排列；
- 每个机会为什么值得做、我们的强观点、标题（title=直白版，titleGuidance=爆点方向）、开头钩子、原始来源和缺失素材；
- WMB 是否保存成功。

只有来源失败或证据缺口影响结论时才报告异常。不输出冗长运行日志，不创建定时器、爬虫平台、评分系统或自动发布流程。
