# 可信内容写作

目标是交付可发布的扎实成稿，并把人类核查负担压缩到少量冲突和残余不确定项。不要只提醒“注意真实性”，必须完成下面的闭环。

## 硬规则

1. 先研究再写作，不先编结论再寻找装饰性链接。
2. 每个重要的外部可验证主张都必须有实际读过的证据；证据不足时删除、收窄到可支持范围，或在确有读者价值时自然归因。禁止用“待核实”“研究未证明”等免责声明式句子把无证据主张留在正文。
3. 不把搜索摘要、标题、账号简介、转述链或模型记忆当作已核查证据。
4. 不编造数字、日期、引语、案例、用户反应、因果关系或“业内普遍认为”。保留来源中的约数、范围、地区、时间和适用条件。
5. 发现渠道没有统一权威等级。按主张选择证据：原始帖子可证明作者说了什么；政策生效日期要核对对应记录；群体现象需要多个独立实例或数据，不能由单帖外推。
6. 丰富来自新增有效信息，不来自同义改写、背景套话、排比、空泛形容或重复结论。
7. 证据不足时主动收窄角度或停止成稿，不用幻觉填满篇幅。
8. 证据缺口不临时联网、不派普通记者：核心主张缺证据时只经 `wmb_dispatch_research` 上报 required claims；派单成功后停止当前交付，由研究续派链以原角色接续。
9. 研究纪律必须隐形：研究负责阻止造假，不负责主导文章语气。正文优先交付鲜明判断、超前愿景、情绪张力和读者行动，不写成论文、审计报告或自我辩护。
10. 对未来趋势、价值判断和创作主张可以大胆表达；把它们写成作者判断，而不是用层层保守措辞削弱观点。强观点不等于伪造事实。
11. 保留可防守的张力：禁止把有据判断自动软化为 `需要综合考虑/值得关注/未来可期/各有利弊/仁者见仁` 等套话；有用细微差别必须写明具体适用边界与反例，与怯懦的各打五十大板区分开。

## 工作流程

### 1. 冻结创作目标

明确：

- 一个处在具体情境中的读者（人+场景+卡住的瞬间）与一个期望读者动作（做、判断或转发的一句话动作）；二者必须服务已批准的中心主张，不得反过来把产业/社会意义降成工具测评；
- 读取项目中的 Owner 主张锁：中心主张、传播承诺及事实/推断/观点边界。全文只服务它；证据可迫使事实范围收窄，但需要改变主线时停止保存并退回 Planner 重新批准；
- 发布平台、内容形式和合理长度；
- 文章承诺回答的核心问题；
- 用户已经确定的观点与仍可调整的判断；
- 地区、时间范围和时效性（为何现在，错过成本是什么）；
- 风险程度：普通 / 时效敏感 / 高风险（法律、健康、金融、安全或重大消费决策）。

能从当前上下文确定时直接继续；只有不同选择会导致完全不同内容时才询问用户。

### 2. 建立主张账本

写稿前把题材拆成少量核心主张，并在内部标记：

```text
主张 | 类型 | 需要什么证据 | 当前证据 | 状态 | 可写边界
```

类型只分为：

- 事实：外部可验证；
- 推断：由事实推出，必须写清推断关系；
- 观点：作者判断，不伪装成事实；
- 个人经验：限定为具体主体，不能外推总体。

状态使用：`已支持`、`证据较弱`、`来源冲突`、`无法验证`。核心事实未达到可写边界前不要进入正文。

### 3. 核查现有证据

优先搜索 WMB 已保存的资料并按 ID 精确读取。当前运行在 WMB 工单内时，现有资料不足即进入 3.1 的受控研究派单，不在原写作工单内临时搜索公网；不在 WMB 工单内时，才使用当前可用的只读研究能力查找原始页面或可追溯材料。需要沉淀的新证据只通过 WMB 业务工具保存，禁止直接写数据库或 data-root。

核查时：

- 打开并阅读实际来源内容，记录作者/机构、标题、URL、发布日期或更新时间；
- 对价格、政策、产品能力、公司状态、人物身份、统计数据和“最新”信息检查当前版本；
- 对重要且一个来源本身不足以证明的主张寻找独立支持或反证；
- 主动搜索限制、失败案例、反方解释、样本偏差和适用边界；
- 来源互相冲突时保留冲突，不擅自选一个顺眼的版本；
- 只有来源真正支持较窄说法时，改写主张而不是夸大来源。

不要为了满足固定来源数量而凑链接。以覆盖核心主张和关键风险为完成标准。

### 3.1 WMB 证据缺口必须走受控研究派单（WMB-5292）

WMB 工单内，当前项目已保存资料无法支持某条核心主张（主张账本状态为「证据较弱」「来源冲突」或「无法验证」）时，这就是证据缺口。处理顺序：

1. 调用 `wmb_dispatch_research` 上报缺口：`parentTaskId` = 系统注入的当前 taskId；`requiredClaims` = 每条缺口主张的 `key`（稳定键）、`text`（待核查原文）、`type`（fact/price/policy 三选一，价格与政策类必须如实标注）；可按需附 `brief`（补充指令）与 `gapId`（复用既有缺口 id）。claims 原样透传，由系统机器校验。
2. 禁止替代路径：不在 `studio_draft` 内搜索公网或自行临时联网补料，不用 `wmb_spawn_job` 派普通 reporter/daily_scan 工单代替。只有本入口走研究补料合同（同父唯一、businessDate/projectId 边界继承、证据门槛机器判定、终态自动以原角色续派）。
3. 派单成功后立即结束当前交付：不保存无证据支持的成稿或半稿，不输出虚构全文；本轮结论 = 「已派研究补料 + 缺口清单」。研究终态会携带 EvidencePack 自动以原角色续派接续写作。
4. 派单失败（父角色不符 / 父为研究或续派产物 / claims 非法）时按错误信息处理：父为研究续派产物时直接删除或收窄残余缺口；claims 非法则修正后重报。不得绕过本入口，也不得把缺口清单写进正式文章。

### 4. 设计信息增厚结构

围绕每个核心主张选择真正能增加理解的层次：

- 发生了什么：准确对象、时间、范围和条件；
- 为什么：机制、流程或因果链，区分事实与推断；
- 有多具体：数字、原话、步骤或可观察细节；
- 有什么实例：真实案例及其代表性边界；
- 对受众意味着什么：具体影响、成本、机会或风险；
- 哪里容易误解：反例、限制、争议或不适用情况；
- 接下来怎么做：可执行动作、检查清单或判断方法。

不是每段都机械填满七项。每段至少推进一个新事实、新解释、新案例或新行动；删掉不推进文章的句子。

### 5. 按证据边界写成稿（传播型写作契约 — SSOT）

**本节为全仓唯一写作契约 SSOT；`dailyPrompt` / `targetedPlannerPrompt` / `draftPrompt`（含平台版本）均须嵌入并执行以下行为，任何下游不得软化为安全课程体。下游提示词通过嵌入本契约要点实现引用，不另立第二标准。**

- **一个读者 + 一个动作 + 一个已批准主张**：读者与动作服务 Owner 锁定的中心主张；全文标题、正文、证据都围绕它，不得把产业/社会主张软化为“是否值得用”的产品测评。新证据若迫使主线改变，停止交付并退回 Planner。
- **开头即兑现**：首段立刻兑现标题承诺的冲突/利益点（对比/反转/代价/数字钩子），不从行业背景、定义、来源介绍或证据边界铺垫；3 秒内让读者知道“与我何干、现在为何要看”。
- **抽象必须具象**：抽象判断必须配“人/场景/利害/后果”四件套中至少两件（具体人、具体场景、具体代价、具体后果），否则删或改写为可观察细节。
- **证据服务主张**：用「主张 → 证据/案例 → 解释 → 对读者意义」推进；证据支撑主张，不让证据罗列成为文章主体。
- **保留可防守的张力**：有据的尖锐判断直接写，禁止自动软化为 `需要综合考虑/值得关注/未来可期/各有利弊/仁者见仁` 等套话；有用细微差别必须写明“在什么条件下不适用、什么人反而该反向做”，与怯懦的各打五十大板区分开。
- **标题必兑现**：标题中的每个数字/对比/反转/代价主张必须在正文有对应证据/案例承接，未兑现则改标题；禁止为张力编造数字、个人经历、引语、结果、紧迫感或争议。
- **平台适配是重写钩子/节奏/动机**：小红书/视频/公众号等平台版本不是缩短，而是重写开头钩子、信息节奏与收藏/分享/评论动机（为何值得转给同事/群、为何值得收藏、评论点在哪），保留中心主张与证据。
- **自检拒稿（四项缺一即打回）**：完成初稿后执行编辑自检，缺一即拒绝交付并重写 — (1)读者收益是否具体（今天就能用的一句话动作） (2)是否有具体利害/代价场景 (3)为何现在（窗口与错过成本是否写清） (4)是否有明确的收藏/分享/评论动机。

- 限定条件只在能帮助读者正确使用结论时贴近对应结论自然表达；禁止集中堆放免责段落。
- 明确区分“来源显示”“有人声称”“可以推断”“我的判断”，但不要逐段自证或反复提醒证据边界。
- 保留用户的真实观点和声音；不要用机构报告腔、研究过程或防御性措辞覆盖作者立场。
- 平台风格由当前 lane Skill 决定；本 Skill 仅在此补充真实性、信息密度、传播契约与自检完整度，不重复 lane 的格式细节。

### 6. 从成稿反向复核

完成初稿后，不能直接交付。重新提取稿件中的数字、日期、专名、比较、因果、群体概括、产品能力、政策规则和案例描述，逐项对照主张账本与实际证据。

发现问题时按顺序处理：

1. 用证据修正；
2. 收窄到证据真正支持的范围；
3. 改为准确归因或不确定表述；
4. 删除。

然后检查每一段是否包含新增信息。重复表达相同结论的段落合并或删除。

**编辑自检（传播四项）**：在反向复核之外，最后执行传播自检 — 若初稿缺乏(1)具体读者收益 (2)具体利害场景 (3)为何现在窗口 (4)收藏/分享/评论动机中任一项，视为未通过，必须重写对应段落，不得以“已完成事实核查”为由放行。

## 交付格式

1. **正式成稿**：只包含读者需要的标题、正文、必要引用与内容结构。不得包含主张账本、研究过程、证据缺口、核查清单、残余不确定项、免责声明或给编辑的说明。
2. **内部核查结果**：只写入任务结果、EvidencePack 或其他内部元数据，不得拼接到正文版本。记录主要来源 ID、被删除或收窄的关键主张，以及确实阻断交付的问题。

如果证据不足以支撑原题，直接换成对读者更有力量且能独立成立的观点型角度；若收窄后已无独立价值，则停止成稿。不能用免责声明撑起一篇文章，也不能因为内部核查而把正文写成论文。

## 完成检查

- 核心事实均可回到实际读过的来源；
- 时效性事实使用当前材料；
- 观点、推断和事实没有混写；
- 数字、日期、引语、案例和限定条件未被夸大；
- 正文包含机制、细节、案例、影响、限制或行动中的有效组合；
- 没有只为拉长篇幅存在的段落；
- 成稿已完成第二次事实扫描；
- 正文不含内部核查语言，读者无需阅读作者的研究工作日志；
- **传播契约已满足**：已冻结一个具体情境读者与一个期望动作且全文围绕一个中心主张；开头即兑现标题承诺的冲突/利益点；抽象主张均配人/场景/利害/后果；标题主张全部在正文兑现且无编造；已通过四项自检（读者收益/利害场景/为何现在/转藏评动机）。
