## 0. 结论先行

1. Owner 人设锁死为「**AI × 个人商业化成长**」：公开用 AI，把自己做成能靠内容和产品活下去的人。五维 = 认知、技能、表达、获客、产品化。
2. 这个方案**不是新赛道、不是新模块**：是给现有 WMB 内核装一份「AI×商业化成长」工作空间配方（A 章），并把审计出的能力现状翻译成今天就能用的操作（B 章）。
3. 审计结论：**叙事主轴五环（收集→整理→判断→创作→复盘）全部「已能用」**，Today 首屏直接回答「今天什么值得做、为什么、怎么讲」。发布/采集是夜灯，X 全格式已能拿真回执，小红书 3/6 缺口不阻塞开跑。
4. 三个 P0 全部是**配置 + 文案 + Skill 提示词**，不动代码：① 工作空间配方拧焦到商业化五维；② 六个内容栏目骨架进编辑简报；③ 情报源增补「独立开发者/一人公司」通道与自有回执入侦察。
5. 一个 P1 需要新 UI（方法库聚合视图），一个 P1 半配置（复盘商业化信号字段），P2 全部是执行环与需求信号工作流，90 天内按此顺序推进。
6. **14 天开跑**：Day 1 军令帖锁人设，之后每日「Today 判断 → 实验/开发日志 → 周复盘」，内容全部源自真实动作，发布走 X 主战场，不强求全平台日更。
7. 中骗边界：预期可超前一个身位（公开开发中、方法成型中）；不伪造战绩、收入、用户数、完成度，不承诺必爆、躺赚、全自动。
8. 当前不阻塞开跑：缺口集中在执行环（夜灯）与方法库聚合 UI（有数据层可先用现有入口），均不碰主灯。

## 1. 人设与产品关系（不让软件抢人设，也不让人设架空软件）

**关系一句话：WMB 是「一个人 + AI 商业化成长」这台戏的现场与账本，不是主角。**

- **人设是主角**：Owner 对外身份 = 公开用 AI 做内容、跑实验、沉淀方法、做产品的一个人。读者关注的是「这个人怎么用 AI 活下去」，不是「这个软件多厉害」。
- **WMB 是现场**：收集、整理、判断、创作、复盘都发生在 WMB 里，所以内容里的每一次「我做了什么」都自带可追溯的现场（资料来源、判断理由、草稿版本、回执）。这让「公开开发」不是口嗨，而是真现场。
- **人设不架空软件**：Owner 的每一篇内容都应该是 WMB 主灯流程（收集→整理→判断→创作→复盘）的产物；不是另起炉灶在外面写，再把 WMB 当截图素材。软件内的工作流即内容的流水线。
- **软件不抢人设**：对外叙事里 WMB 只作为「实验对象/现场」出现（「我搭的自媒体终端」），**不写成**「我用 WMB 帮你做号」的 SaaS 口吻。主菜永远是收集→整理→判断→创作→复盘；发布、自动化、回执提一句即可，不当前主角（Narrative Priority 不可反）。
- **两者互相验证**：人设需要「真实实验可见」的眼前肉（卡住点、AI 插手、产出、无效步骤）——这正是 WMB 记录的；WMB 需要人设提供「为什么做这个」的编辑目标——这正是工作空间配方的输入。配方拧焦了，两者就咬合。

## 2. A. 工作空间配方（可配置、可粘贴进设置/能力包）

> 本章全部字段面向「编辑/受众/选题」配置，是可粘贴进 workspace profile、编辑简报、Skill 提示词的原文。人设锁定句贯彻全章：终局 = 一个人 + AI 稳定产出内容、沉淀方法、做成产品；过渡 = 公开开发 + 自己当小白鼠；眼前肉 = 真实实验可见。

### A1. workspace 显示名建议

- 中文：**「AI × 商业化成长」**
- 英文：**AI × Solo Commercialization**
- 备选（若嫌长）：「个人商业化」/「AI 变现实验」。不建议沿用「AI」——显示名要替 Owner 提醒编辑身份，不替读者泛化。

### A2. 一句话编辑使命

> **公开用 AI 做内容、跑实验、沉淀方法，把自己做成一个能靠内容和产品活下去的人。**

对齐对象：Owner 对外身份。每次编辑判断（选题、角度、表达）都以这句话为最终裁决者——「这条内容帮不帮『一个人靠内容和产品活下去』？」

### A3. 受众画像（可观察特征，非虚词）

1. 已经在用 AI 干活（写代码、做内容、跑工作流、接单），不是纯围观者——他们会追问「怎么复现」。
2. 想靠「内容 → 信任 → 付费」链条获得独立收入，但还没跑通，对「变现」「接单」「产品化」话题有真实痛点。
3. 反感空喊风口与躺赚话术；吃真实实验、真实卡点、真实回执，能分辨「用过」和「装用过」。
4. 关注 AI 工具/Skill/工作流实测与独立开发者实践（X 活跃，中文为主，小红书/公众号为辅）。
5. 提问具体（「这个怎么搭」「要多少钱」「踩了什么坑」），不满足于摘要式资讯。

### A4. 核心承诺

> **关注 = 每篇带走一个可执行的 AI 用法或一条真实实验记录；长期看，学会一个人用 AI 把内容和产品做出来、活下去。**

关注后三周内能兑现的三件小事：① 至少 10 条可直接抄的实验/方法；② 一套「今天做什么、为什么、怎么讲」的判断习惯；③ 看到一个人从零公开开发的完整过程（含失败与无效步骤）。

### A5. 选题四问（每日判断强制问题）

对齐现有 editorial brief / 四问传统（值得知道·值得讨论·值得尝试·拿去赚钱），拧到商业化五维。**每一条候选机会必须过四问，四问全不过不入 Today 主菜。**

1. **值得知道**：它改变了「一个人靠 AI 内容和产品活下去」的哪个环节（认知 / 技能 / 表达 / 获客 / 产品化）？说不出环节 = 泛资讯，降权。
2. **值得尝试**：受众或我自己能立刻动手试什么？真实代价（时间/钱/门槛）是什么？说不出可动手动作 = 空谈，降权。
3. **值得讨论**：我有没有非复述的强观点或实验证据？「AI 官方发布了 X」不是观点；「X 改变了接单报价的哪个环节，因为我试了/看到谁试了」才是。没有 = 让给官方号，降权。
4. **值得赚钱/做成产品**：它背后藏着什么问题、什么需求信号？问题出现 ≥3 次才成立需求信号，1 次是噪音。没有 = 没关系，但别硬造。

### A6. 机会过滤器

**提高优先级的信号（进 Today / 打高优先）：**

- 直接命中五维之一，且能说清命中的是哪个环节；
- 有真实实验/实测证据（自己跑过，或可复现的一手案例）；
- 一手/官方来源 + 时效性（发版、发布、政策、工具上新）；
- 受众重复问题的社区证据（X List 讨论、评论区、私信原话 ≥2 处）；
- 一条素材能同时支撑「内容 + 方法沉淀 + 潜在需求信号」三层产出。

**直接降权/移出的信号（对接 lane-gate 思维，移出走「不相关 → archived」同事务）：**

- 纯复述公告、零观点增量（官方新闻稿搬运）；
- 无法验证的赚钱承诺、风口叙事（「XX 躺赚」「XX 是下一个风口」）；
- 与「一个人活下去」无关的宏大行业综述（巨头财报综述、千亿市场盘点）；
- 一次性热点、无沉淀价值（追完就丢，不给方法/资产留东西）；
- 需要我编造实验或经验才能写（→ 直接 kill，写出来就是大骗）。

### A7. 内容栏目（6 个）

> 每个栏目：`名称 | 占比建议 | 触发条件 | 固定骨架 | 成功信号 | 禁用写法`。占比是 14 天窗口的松约束，不是日更指标。

**1. 实验日志（AI 实测）**
| 占比 30% ｜ 触发：完成一次真实使用/搭建/踩坑（工具、Skill、工作流、提示词）｜ 骨架：目标 → 我做了什么 → AI 插手点 → 卡点 → 结果/回执 → 无效步骤 → 下一步 ｜ 成功信号：被收藏、追问「怎么复现」 ｜ 禁用写法：云评测、假装用过的体验、罗列功能的说明书。

**2. 开发日志（公开开发，自己当小白鼠）**
| 占比 20% ｜ 触发：WMB 或任何自有产品有实质进展或卡点 ｜ 骨架：今日一刀（做了什么）→ 回执（结果/数据/截图）→ 余味（明日预告，制造期待感）｜ 成功信号：读者跟进度、私信催更、有人问「这工具什么时候能用」｜ 禁用写法：无回执的「我在做大事」、只报喜不报忧、把工程细节当主菜（回执/架构自嗨）。

**3. 原则卡（判断/方法）**
| 占比 15% ｜ 触发：复盘/实验中提炼出可复用判断 ｜ 骨架：一句话判断 → 物证（实验或案例）→ 适用边界 → 反例 ｜ 成功信号：被截图转发、被引用到别人的内容 ｜ 禁用写法：无物证的道理、鸡汤化、只讲对不讲错。

**4. 机会判断（今日值得做）**
| 占比 15% ｜ 触发：Today 出现 SSS/S 级机会且四问全过 ｜ 骨架：为什么现在 → 我的强观点 → 标题爆点 → 开头钩子 → 原始来源/缺失素材 ｜ 成功信号：打开率高、评论区有观点交锋而非纯转发 ｜ 禁用写法：热点链接合集、无来源的判断、标题与正文不符。

**5. 周复盘（商业化信号）**
| 占比 10% ｜ 触发：每周固定一次 ｜ 骨架：兑现了什么 → 图景是否还真 → 追问原话 → 重复问题列表 → 需求信号 → 下周 K/S/C ｜ 成功信号：读者说「学到了复盘方法」、开始有人带着自己的复盘来问 ｜ 禁用写法：数据流水账、只有 Keep 没有 Stop、把周复盘写成月度总结的压缩版。

**6. 变现实验（收入/获客）**
| 占比 10% ｜ 触发：真实成交或真实失败（接单、报价、小产品、付费内容）｜ 骨架：场景 → 报价 → 过程 → 结果 → 教训 ｜ 成功信号：私信咨询「怎么开始」、被问「能不能带/有没有课」（= 需求信号）｜ 禁用写法：未发生的收入炫耀、把「有人问」说成「很多人买」（大骗）。

### A8. 14 天内容日历逻辑（生成规则，不排具体日期）

- **规则 1（素材来源）**：所有内容必须源自真实动作——Today 判断、实验、开发、复盘、变现。禁止为了日更从外部热点硬凑。
- **规则 2（节奏）**：Day 1 军令帖（锁定人设：终局/过渡/眼前肉，含期待感）；Day 2–14 每工作日 1 篇，实验日志与开发日志交替为主，机会判断跟着 Today 的 SSS/S 走（不强求固定频率）；每周 1 篇原则卡（从本周实验/复盘提炼）+ 1 篇周复盘；变现实验只在有真实事件时出现。
- **规则 3（判断先行）**：每天先开 Today 做四问，再决定今天写什么。写之前没有四问通过，就不写——空窗一天优于硬凑一篇。
- **规则 4（发布夜灯）**：内容成型 → 浏览器准备 → 人工点发布。主战场 X；小红书走「复制成品人工贴」；公众号可选。不追求三平台同日全发。
- **规则 5（留痕）**：每篇在 WMB 里至少关联 1 条入库资料；发布后留回执；每周复盘把 method_findings 汇总进周复盘内容（一举两得：方法库无聚合 UI 时的替代出口）。
- **规则 6（中骗自检）**：每篇写完后跑一遍「剂量自检」（见 A10），发虚表达 ≥5 处就改完再发。

### A9. 情报源配置建议

- **官网类（W1，primary + release）**：沿用现有 source-index 的 AI 官方源（OpenAI / Anthropic / Google DeepMind / Meta AI / Mistral / DeepSeek / ByteDance Seed / 即梦 等），**增补商业化视角源**：AI 开发平台定价页、API 价格/模型更新页、独立开发者常用的服务商公告、AI 接单/外包平台的规则变化（如平台抽成、结算政策）。
- **X List 类（W0）**：保留现有 AI 前沿 List（list_id=2082851520417255750）；**新增三类 List**：① 独立开发者/一人公司（levelsio、Marc Lou 类，看产品化与变现实验）；② AI 工具实测类（看复现型内容）；③ 中文 AI 创业者/自媒体类（看中文受众语境）。List 绑定/成员变更走现有 execution grant + UI 确认流程，不新增权限路径。
- **社区需求（W2，Pi 主题航线）**：小红书/公众号评论区、X 回复、私信中的**重复问题**作为需求信号收录（原话记录 + 出现次数），进入复盘商业化信号字段。
- **自有产品/开发进展进入侦察**：把「自有进展」当作一个固定素材通道——每次实验/开发完成后，把结果 + 无效步骤留一条**回执**（先复用现有资料/内容项目录入路径，如 source 或 content project notes）；回执经 Today/复盘进入选题候选。**先跑习惯，不先造新模块**：本周回执 → 下周可能就是一条实验日志或原则卡的素材。

### A10. 表达边界

- **中骗剂量（可拉高）**：预期超前一个身位——「正在公开开发」「方法成型中」「第一天的小白鼠」可以说；「从零到一的过程完整可见」可以说；但预期必须跟着兑现走：承诺下周发的，下周要有回执。
- **不可造假（红线）**：伪造战绩/收入/用户数/完成度；暗示「跟我干必爆」「躺赚」「全自动无人值守」；把「有人问」说成「很多人买」；把「计划做」写成「已上线」。以上任何一条 = 大骗，一票否决，整篇重写。
- **WMB 在内容里怎么提（主菜/配菜）**：WMB 是**配菜/现场**，不是主菜。提法：作为实验对象自然出现（「我搭的自媒体终端今天帮我判断出……」），一句话带过；**不写**「WMB 帮你自动发帖」「我们的 SaaS 终端」等抢人设表述。主菜永远是收集→整理→判断→创作→复盘。

### A11. 复盘模板

在 Keep/Stop/Change 之外，增加「商业化信号」三件套（先映射到 ReviewRecord 的 summary/notes 等现有字段，跑两周真实数据再决定是否加专用字段）：

1. **追问**：本周每篇内容带来哪些私信/评论/追问？抄原话（≥2 条原话，标注来自哪个平台哪篇）。
2. **重复问题**：哪些问题出现 ≥2 次？列出问题原话与计数；≥3 次 → 需求信号候选，进入 P2 需求信号工作流。
3. **需求信号**：有没有人主动问「有没有工具/模板/服务/课程」？有没有可交付的最小形态（清单、模板、提示词包、陪跑）？记下形态假设，不立项。
4. 固定四段：**兑现了什么**（本周承诺 vs 回执）｜ **图景是否还真**（人设一句话还成立吗）｜ **五维偏科检查**（认知/技能/表达/获客/产品化哪一维欠账）｜ **下周 K/S/C**（具体到动作）。
5. 收尾动作：结论写入 method_findings，供下一轮 plan 引用（validateReferences 要求 status='final'，复盘先 final 再被引用）。

### A12. 方法库种子原则（12 条，可进 method_findings 的表述级）

1. 内容先于收入，信任先于交易；没有信任积累的变现是消耗。
2. 公开开发是最好的信任设计：过程可见 = 无需自证的诚意。
3. 预期超前一个身位，兑现紧跟其后；承诺与回执必须成对出现。
4. 没有回执的开发日志不如不写；回执（结果/数据/截图）是公信力的货币。
5. 重复问题 ≥3 次才是需求，1 次是噪音；先记原话，不急着做产品。
6. 判断要能追到资料，观点要能追到实验；无来源的断言不入库。
7. 主菜是判断与创作，发布是夜灯；把执行环当主角就是叙事跑偏。
8. 无效步骤是收据：记录踩坑本身就是资产，失败实验和成功实验同价。
9. 一个明确首选胜过十个平铺机会；Today 首屏只推一个主菜。
10. 先服务真实账号，不先做通用产品；自己做小白鼠是第一用户。
11. 内容是产品化的最小原型：每篇内容都在测试一个可交付形态的假设。
12. 卡点比亮点更值得写：读者记住的是「你也卡过，然后呢」。

## 6. 非目标与保险丝

### 非目标（本方案明确不做）

- 不做自动发帖：WMB 不点击任何平台的最终发布按钮，小红书发布保持人工；「自动发帖工具」叙事一票否决。
- 不承诺赚钱：不写「稳赚」「必爆」「跟做就有收入」；变现实验栏目只在真实事件后出现。
- 不做通用 SaaS / 不新开产品品类：不是「成长 App」，是现有 WMB 内核 + 配方拧焦；先服务 Owner 真实账号。
- 不新建第二个 UK 工作空间，不改 PRD/TASKS 正式正文（后续只以「PRD 补丁要点」建议形式出现）。
- 不做视觉 UI 大稿（无 mock 大片）；不写 14 天逐日发帖全文（给规则与 Day1 骨架）。
- 方法库聚合视图等新 UI 只进 P1/P2 排期，不因本方案插队。

### 保险丝（跑偏即停，可观察）

1. **叙事跑偏**：内容或对外话术出现「自动发帖/批量生成」叙事 → 停，回到主灯顺序（收集→整理→判断→创作→复盘），发布退回夜灯。
2. **无回执**：实验日志/开发日志开始写没发生过的事（无回执的「体验」）→ 停发该栏目，回到真实动作；连续两次 = 该栏目暂停一周。
3. **主灯被抢**：投入发布自动化/多平台适配的时间超过投入判断与创作的时间 → 停，夜灯不许抢主灯。
