# 固定身份员工 Agent 的 UX/IA 设计（记者 / 编辑 / 资料员 / 主编席助手）

日期：2026-08-07
作者：RoleAgentsDesigner（设计意见，无代码改动）
依据：PRODUCT.md C1–C7、PRD §2.0/§4、docs/spark/2026-08-07-product-form-agent-desk-constitution.md、2026-08-06-today-daily-intelligence-mainline-design.md、pi-dock.tsx / pi-dock-header.tsx（只读审计）

## 0. 结论（verdict）

**把「固定角色」实现为覆盖层（identity layer），而不是新页面、也不是新聊天客户端。**

- 角色**不新增一级导航页**：记者的科室 = 发现（前线），编辑的科室 = 创作（写字间），资料员的科室 = 资料库（资料室），沿 C6 房间隐喻——房间已经存在，角色是住进房间的人。
- 角色可见性 = 三层：**今日员工状态条（值班牌，≤1 行知情）** + **各科室页内的员工名牌与状态** + **dock 收件人名牌（说话对象）**。可选折叠「班组抽屉」承载跨角色监工，默认不展开、不是首页。
- 对话模型 = **单 dock + 收件人切换**：默认收件人是主编席助手（桌上的人）；点角色名牌即「给这位员工打电话」；每角色独立会话线程与独立 worker 租赁（直接化解「单 Pi 租赁卡死全部 Pi 工作」痛点），但界面仍是同一个 dock，不是 4 个聊天窗。
- 派工 = **单跳有界任务**：主编 → 一个角色 → 呈报回主席台（可批）。禁止自动多跳链路与画布连线（防编排回潮）。
- 角色身份 = 系统提示词 + 专属 Skill + 模型预设（设置页一次性配置）；对话内不出现模型选择器（anti-goal 3）。

一句话：**人是主编，桌是今日，电话是 dock，班组是值班牌；角色各有科室，不新盖楼。**

## 1. 设计边界（对 anti-goals 的硬承诺）

1. 无 workflow canvas 连线：角色之间永远没有边。「记者扫完自动交编辑」这类自动链路不做——顶多是主编一次点两张派工单。
2. 无健康大屏：员工状态条只回答「谁在干什么、卡在哪、要不要你拍板」，不回答「系统资源 / 节点状态 / 心跳」。
3. 无每消息模型选择：模型是角色预设的一部分，在设置里配，对话面零模型控件。
4. Today 仍是主编办公桌（C2）：状态条是「今日运行状态」的知情投影，不是第二套首页、不是运行台账。

## 2. IA 图


## 3. 员工状态条（roster strip）规格

位置：今日命令条下方，单行 4 名牌。规则：

- **一行封顶**。每名牌 = 状态点 + 角色名 + 状态词（待命 / 工作中 / 等你批 / 卡住了）+ 一句话（如「扫渠道 3/5」）+ 两个小动作（交谈 / 去科室）。
- 状态点 = 颜色 + 文字双编码（WCAG AA，禁止颜色单通道）。
- 「等你批」：编辑交了初稿等批、记者等确认入库范围——指向真实可批对象，点击跳主席可批清单（必须是可点可操作对象，沿用 TodayRunView blockers 规则：无 action 不上状态条）。
- 「卡住了」：仅真实 blocker（如渠道登录失效）才出现，带修复 action 链接。
- 折叠态：收成单个「班组」胶囊，不常驻两行。
- 不做日志流、不做资源指标：那是健康大屏，不是值班牌（C2/C7）。

## 4. Dock 模型（收件人切换 + 每角色会话/租赁）

- 单一 dock，头部名牌栏 = 收件人选择器（分段控件 4 枚：主编席助手 / 记者 / 编辑 / 资料员）。默认主编席助手。
- 切换收件人 = 切换该角色的会话线程与上下文（系统提示词 + Skill 集合 + 页面焦点对象沿用现有 piContext 机制）；转录不混流（每角色独立 session，session 菜单按班组分节）。
- **每角色独立 worker 租赁**：记者扫渠道占记者租赁，编辑写稿占编辑租赁，互不阻塞——直接化解「单 Pi 租赁卡死全部 Pi 工作」痛点。
- 租赁空闲策略：角色无任务无对话 N 分钟（建议 5）挂起释放；挂起态 = 「待命」灰点。并行租赁不失控。
- 会话菜单按班组分组（主编席 / 记者 / 编辑 / 资料员），新建会话落在当前收件人。
- 权限 chip 语义：现有按页 dock 自动授权不变；派工 = 按任务 intent 签发 grant（复用 task-grants.ts 模型），角色身份**不放大权限**（PRD §4.7 / REQ-027）。
- 状态行不显示模型名；显示「员工在干什么」。

## 5. 交互流

### F1 默认对话（主编席）
1. 开 WMB → 今日桌。开 dock → 收件人 = 主编席助手。
2. 「今天有什么要批的？」→ 主编席读桌态（可批递案 / 今日运行状态 / 在写任务），答 1–2 份递案 + 理由 + 资料追溯（PRD 4.2：判断必须可追溯）。
3. 「把《…》交给编辑」→ 派工单卡（收件人=编辑、交付物、一句要求）→ 确认 → 编辑独立租赁开工；主编席回报「已派。编辑在写。」无进展时禁止编造完成时间。

### F2 点记者问进度
1. 今日状态条点记者 → dock 收件人切为记者 + 焦点给 dock（**不跳页**；点选 ≠ 导航，对齐 pi-page-context 审计契约）。
2. 「扫到啥了」→ 记者答渠道回执摘要（N/M 完成、最新来源、卡点），可引用来源。
3. 「把这条标优先」→ 轻量派工（单跳）。点状态条「去科室」→ 进发现房间看流水。

### F3 记者忙时派编辑（并行租赁——本设计主战场）
1. 记者正在扫渠道（今日情报 running；旧模型下全 Pi 被占）。
2. 主编在选题页批一题 → 卡上「交给编辑」→ 派工单 → 确认。
3. 编辑用自己的租赁开工，与记者并行；状态条同时亮两颗「工作中」。
4. 编辑交稿 → 呈报回今日主席可批；记者扫完 → 今日情报完成态。互不等待。
5. 主编席可一次汇报两线：「记者 4/5 渠道完成；编辑初稿已交等批。」

### F4（可选）班组抽屉监工
状态条展开 → 班组抽屉：三线一屏（谁在干什么 / 卡在哪 / 等你批 N）；只读监工 + 派工入口；关闭即回桌，不进首页。

## 6. 每角色动作矩阵

| 角色 | 科室页 | 动作（UI 呈现为派工/科室动作，非工具面板） |
|---|---|---|
| 记者 | 发现 | 开始/继续今日情报（今日命令条既有入口）；暂停/停止采集；条目「入库/核验」；调整采集范围（进设置） |
| 编辑 | 创作 | 派写（选题卡「交给编辑」）；继续 / 改稿 / 交付；交付 = 呈报回主席可批 |
| 资料员 | 资料库 | 开始整理；校验；移出 / 恢复（既有 lane 判定）；「挂到主题」 |
| 主编席 | 全站 | 问进度；派工；批递案；把任意对象「交给某角色」 |

## 7. 空 / 忙 / 卡文案（敏锐克制主编台）

| 态 | 文案（示例；禁止猜测性措辞） |
|---|---|
| 记者待命 | 「记者在待命。今日情报未开始——桌上点「开始今日情报」。」 |
| 记者工作中 | 「记者扫渠道中 · 3/5 · 最新：{来源}」 |
| 记者卡住 | 「渠道 {X} 需要登录校验 → 去设置修复」 |
| 编辑待命 | 「编辑待命，没有在写任务。」 |
| 编辑等你批 | 「编辑等批：《{题}》初稿已交 → 主席可批」 |
| 资料员空 | 「资料室无待整理。新料入库后会排给资料员。」 |
| 资料员工作中 | 「资料员整理中 · 待归档 {N} · 已归档 {M}」 |
| 主编席默认 | 「主编席在。今日有 {N} 份递案等批。」 |
| 全忙 | 「记者与编辑并行工作中，互不影响。可分别催。」 |

规则：永远回答「谁 + 在干什么 + 卡在哪 + 主编能做什么（等 / 催 / 批 / 派）」。

## 8. 视觉 / 组件笔记

- 角色色先入设计系统 token 再使用（禁止散落硬编码 hex）：记者 = 青蓝（前线采集）、编辑 = 琥珀金（写作台灯）、资料员 = 墨绿（档案）、主编席 = 中性墨。
- 名牌 = 角色字标/单字母 + 名字 + 状态点；不画卡通头像、不用渐变玻璃、不发光边框（avoid 清单）。
- dock 名牌栏为分段控件：切换即时、无加载转场；reduced motion 下状态点静态。
- 状态点：待命=灰、工作中=琥珀（无脉冲）、等你批=蓝、卡住了=红；颜色+文字双编码。
- 派工单卡：收件人 + 交付物 + 一句要求 + 确认按钮；确认后折叠为一行「已派」。
- 会话分组：按班组分节 + 当前会话高亮；归档语义沿用现有 session 菜单。

## 9. 风险

1. **聊天客户端漂移**：每角色会话 + 名牌可能把 dock 变成聊天首页。缓解：今日仍为桌、dock 是工具、默认收件人主编席、dock 不进首页。
2. **编排回潮**：派工诱使自动多跳（记者→编辑链路）。缓解：单跳有界派工契约、呈报回主席台、UI 永不出边。
3. **租赁成本失控**：并行租赁放大 Pi worker 数。缓解：空闲挂起 + 全局暂停 + 每角色租赁上限。
4. **身份 vs 授权混淆**：角色身份不得自动放大权限。缓解：派工 = 按任务 intent 签发 grant（复用既有模型）；角色名牌不是权限证书。
5. **状态条噪音**：值班牌可能膨胀成迷你健康大屏。缓解：一行封顶 + 只放知情项 + 流水进科室页。
6. **双答混淆**：主编席谈记者工作时必须读到记者真实状态。缓解：角色状态投影进主编席上下文（共享事实源，PRD 4.1；需新增 role-status 投影 API）。
7. **模型预设回漏进对话**：per-role 模型若实现不当会回漏选择器。缓解：设置页一次性配置，对话面零模型控件（回归断言）。

## 10. Owner 锁定问题

1. **dock 收件人模型**：单 dock + 名牌切换 + 每角色独立会话/租赁（vs 多聊天窗口）。建议前者。
2. **班组呈现面**：今日一行状态条 + 科室名牌 + 可选折叠班组抽屉；不新增一级「班组」页。是否接受可选抽屉？
3. **派工边界**：单跳有界派工、呈报回主席台；禁止自动多跳。是否锁定？
4. **角色预设范围**：系统提示词 + Skill + 模型预设均设置页配置，对话内无模型选择器。是否锁定？
5. **通用 Pi 身份去向**：主编席助手取代通用「Pi」为默认身份；是否保留无角色限定的「Pi」回退（不默认）。需要 Owner 二选一。

## 11. 兼容注记（与 role-permission 设计对齐，2026-08-07）

本稿初版按会话给定角色清单（记者 / 编辑 / 资料员 / 主编席助手）写作。RolePermDesigner 的 `docs/spark/2026-08-07-role-permission-design.md` 按 Owner 约束把「编辑」拆为两岗：**策划**（选题/主题/结果 科室，选题决策者；writer 不是 topic decider）+ **写手**（创作 科室）。对齐结论：

- 值班牌 5 枚：桌助 / 记者 / 策划 / 写手 / 资料员。
- 本文 §3 状态条与 §4 dock 收件人切换按 **N 槽泛化**，拆岗零成本：名牌行 4→5，其余规格（一行封顶、状态点双编码、按班组分组会话、独立租赁与挂起）不变。
- 科室映射调整：策划住 选题/主题/结果，写手住 创作；§2 IA 图与 §6 动作矩阵按此拆解（「交给编辑」→「交给策划定题 / 交给写手起草」）。
- 派工、授权与角色权限契约以 role-permission 文档为准；本文只承载 UX/IA 层。
- **修订（canonical §7）**：Owner 要求一级「智能体（班组）」页（roster 谁在干什么 + 进度 + 详情 + 设置跳转），今日只留一行值班条（点「查看全部」进智能体页）；本文 §3/§10 的「可选折叠班组抽屉」方案废弃，被整页取代。值班条与 dock 名牌规格不变。
