# WMB 模块化赛道工作空间设计

- 日期：2026-08-02
- 状态：用户已书面认可；两轮共六路独立对抗性审计已裁决并同步正式契约
- 性质：`PRD.md`、`SPEC.md`、`PLAN.md`、`TASKS.md` 和 `TECHNICAL_DESIGN.md` 的详细设计说明

## 1. 决策摘要

WeMediaBuddy 的长期底层不是“AI 赛道软件”，也不是覆盖编程、设计等任意工作的通用 Agent 平台。它是一套赛道无关的人机协同自媒体创作与运营终端。

产品固定保留完整自媒体闭环：

> 情报与素材进入 → 核验整理 → 机会判断与策划 → 人机共同创作 → 平台适配 → 人工发布 → 数据采集 → 复盘并改进下一轮

一个 WMB 安装可以登记多个相互隔离的赛道工作空间，例如 AI、英国生活以及未来由用户提出的其他自媒体赛道。每个工作空间使用 WMB 官方提供的能力包形成自己的“内容生产线配方”。用户不手工编排模块；Pi 或外部 Agent 根据用户的自然语言目标生成完整提案，WMB 做确定性校验，用户查看准确结果并确认后才启用。

对抗性审计确认：首期不把同一个 SQLite 数据库改造成多租户数据库。**一个工作空间就是一个完整 WMB data-root；同一时间只激活一个工作空间运行时。** 这能直接复用现有数据库、素材、浏览器登录态、Pi 会话、小红书运行目录、日志和恢复规则，同时避免全库重建唯一键与外键。

本阶段不建设第三方插件机制、自由节点工作流、通用工作流引擎、并行多工作空间运行时、多人权限系统、云服务、原生图片编辑器或原生视频剪辑器。

## 2. 根问题与现有证据

当前 WMB 的情报、资料、创作、发布、结果和复盘闭环具有跨赛道复用价值，但产品契约、信源、内容分类、评价规则和 Skill 主要围绕 AI 赛道书写。原 UKLifeContent 终端又实现了一套相似的本地桌面、统一业务 API、MCP、Pi、资料、内容和素材能力。

继续维护两套终端会重复实现业务对象、UI/MCP 共用内核、发布与复盘，以及本地数据正确性验收。根因不是“缺一个 UK 页面”，而是稳定的自媒体内核与可变化的赛道内容尚未形成明确边界。

现有代码同时给出了最短隔离路径：

- `data-root` 已集中包含 `wmb.db`、`assets/`、`browser-profile/`、`logs/` 和 `exports/`；
- Pi 会话、Pi workspace 和小红书 MCP cookies/runtime 也按 data-root 保存；
- MCP Server 创建时绑定一个明确 root，并使用随机 loopback 端口；
- 主进程当前只有一套 Pi、MCP、浏览器和小红书运行时；
- 当前数据库大量约束是根内全局唯一，包括资料 URL/指纹、每日当前方案、平台账号、素材哈希、主题 canonical key 和任务幂等键。

因此，共享数据库内加入 `workspace_id` 会横切现有全部表、JSON 引用、业务命令、幂等账本和运行时；独立 data-root 则天然允许 AI 与 UK 保存相同 URL、主题、日期、平台账号和素材哈希而不串线。

## 3. 产品边界

### 3.1 WMB 固定负责

- 本地单用户桌面工作台；
- 人类界面、内置 Pi 和外部 Agent 操作同一业务状态；
- 资料、选题、方案、内容项目、不可变版本、素材和平台版本；
- 人工确认、网页发布交付、结果采集和复盘；
- 持久任务、错误、停止、恢复和操作读回；
- 多个相互隔离的自媒体赛道工作空间；
- WMB 官方能力包的固定登记、确定性校验和调用；
- 工作空间列表、重启式切换和移动后重新关联。

### 3.2 赛道工作空间负责

- 账号定位、目标受众和内容目标；
- 信源集合、采集范围和关注主题；
- 核验规则、证据标准和机会判断标准；
- 内容分类、创作方法、语气、禁用表达和模板；
- 启用的平台、内容形式和官方能力包；
- 该赛道独立积累的资料、内容、结果、复盘和方法库。

### 3.3 明确不做

- 编程、产品设计、销售等非自媒体工作空间；
- 用户手写代码或拖拽任意节点来重建 WMB；
- 任意顺序、任意分支的 DAG/工作流编排器；
- 第三方可安装代码插件或插件市场；
- 让 Agent 绕过业务命令直接写数据库或业务文件；
- 将工作空间配置只保存在一次 Pi/Agent 聊天中；
- 非活动工作空间在后台继续运行 Pi、浏览器或定时任务；
- 当前阶段建设图片精修、视频剪辑或通用媒体生成框架。

## 4. 工作空间就是完整 data-root

WMB 继续保持一个 Electron 模块化单体和一套业务代码。应用级注册表只保存工作空间身份、位置、活动选择和崩溃恢复用切换日志，不保存内容业务数据、凭证或配方提案。未确认提案只存在当前 Main 进程内。

```text
一个 WMB 安装
├─ 工作空间注册表
├─ WMB 官方能力包目录
├─ AI 工作空间 → J:\...\WMB-AI\
│  ├─ wmb.db
│  ├─ assets/
│  ├─ browser-profile/
│  ├─ pi-agent/
│  ├─ xiaohongshu-mcp/
│  ├─ logs/
│  └─ exports/
└─ UK 工作空间 → J:\...\WMB-UK\
   └─ 同一套根目录结构
```

注册表中的每个工作空间至少包含：

- 稳定 `workspace_id`；
- 显示名称；
- data-root 绝对路径；
- 活动选择由注册表单独记录；
- 切换期间额外记录 `previous`、`pending` 与尝试状态。

每个 data-root 在既有 `app_meta` 中保存匹配的 `workspace_id`。打开、移动或重新关联根目录时，WMB 必须核对注册表与根内身份，不能只按名称或路径猜测。

现有用户 data-root 原地登记为内置 AI 工作空间。除新增工作空间身份和配方记录外，不移动文件、不复制数据库、不重写既有业务对象 ID，也不改变当前根内的唯一性语义。

重命名、归档、删除和并行运行不在首期范围；只有稳定 ID 的移动后重新关联属于当前合同。

## 5. 单活动工作空间与切换协议

首期同一时间只允许一个工作空间运行。当前 WMB 的 SQLite、Pi、MCP、浏览器、小红书 MCP、scheduler 和 renderer read model 都绑定活动 data-root。

### 5.1 切换前置条件

- 存在运行中的 Pi turn、每日情报、内容生成或复盘任务时，拒绝切换，用户先停止、保存部分结果或等待完成；
- 存在发布、X List 等外部写入或无法安全中断的浏览器操作时，拒绝切换，当前原子动作先完成并读回；
- 主进程关闭 mutation gate 后必须能排空当前数据库/文件写队列，否则拒绝切换；
- 只读页面且没有未决写入时可以切换；
- “AI 能继续开发”指允许一次有界冷切换且迁移后能力零回退，不承诺模型 turn 或页面动作跨工作空间零停机。

### 5.2 冷切换顺序

1. 关闭 mutation gate，拒绝新写并排空已接收写入；
2. 确认当前无不安全任务；
3. 只读验证目标 root 的结构与 `workspace_id`；
4. 在注册表写入 `previous + pending`，但不提前修改 active；
5. 停止当前 Pi、浏览器、小红书 MCP、scheduler 和 MCP Server，关闭数据库；
6. 调用 Electron 正常重启，不在同一进程重绑 renderer；
7. 新进程把 pending 标记为 attempting，按正常事务迁移与核心业务读回打开目标 root；
8. 目标健康后才提交 active、清除切换日志并启动其余运行时；
9. 目标失败或 attempting 期间崩溃时恢复 previous；previous 也无法打开则明确报告恢复失败。

失败尝试只允许改变目标根的 schema/migration 元数据与诊断日志，不得改变内容业务对象。每个 journal 阶段都必须支持故障注入和冷开恢复。

MCP 切换时关闭旧随机端口并生成绑定新 root 的新 URL。设置页和连接发现信息同时显示当前 `workspace_id`、名称和 MCP URL；旧 URL 必须失效，外部 Agent 重新连接后先读回当前工作空间，不能自动重连到另一个赛道继续写入。

非活动工作空间不运行后台任务。再次激活时，安全指标任务沿用现有 overdue 恢复语义，记录真实采集时间；不伪造准点快照。发布和其他不安全任务仍进入 `needs_user` 或现有明确状态，不自动重放。整应用重启会销毁旧 renderer、promise 与 IPC 事件，不需要把 workspace epoch 扩散到全部业务响应。

## 6. 固定主线与可替换工位

“生产线”是产品责任边界，不是强迫创作者单向前进的自动流水线。用户与 Agent 可以在资料、判断、创作和平台版本之间往返，但 WMB 不允许任意创造新的业务阶段。

| 固定工位 | WMB 固定产物 | 可由官方能力包变化的内容 |
| --- | --- | --- |
| 情报与核验 | 可追溯资料、证据、核验状态和缺口 | 信源目录、采集 Skill、核验规则和工具路线 |
| 机会判断与策划 | 选题、优先级、运营方案和引用 | 受众价值、评分规则和创作角度 |
| 内容创作 | 内容项目、观点、版本和素材关系 | 写作 Skill、模板、语气和内容形式 |
| 平台适配与发布 | 明确平台版本、账号、有序素材和发布结果 | 已支持平台的模板与固定适配器 |
| 结果与复盘 | 指标快照、Keep/Stop/Change 和方法结论 | 赛道指标解释和复盘方法 |

知识库、关系画布、任务和 Pi 上下文属于贯穿各工位的共享业务能力，不另建平行生产线。

## 7. 最小官方能力包目录

首期不建立通用模块运行时或依赖求解器。官方目录在编译期由 WMB 代码与随包资源定义，只提供有限、粗粒度插槽：

| 插槽 | 基数 | 首期含义 |
| --- | --- | --- |
| `intelligence_pack` | 恰好 1 个 | 一个完整的赛道情报与核验包，可内部固定调用多个 Skill、collector 和 MCP 工具 |
| `creation_pack` | 恰好 1 个 | 一个完整的赛道写作方法、语气和模板包 |
| `platforms` | 1 至多个 | 从 WMB 已支持的平台与格式中选择启用子集 |

复盘继续使用 WMB 固定内核；AI/UK 尚未证明存在需要独立执行包的真实差异，因此首期不预建 `review_pack`。

一个能力包可以在其内部使用多项既有工具，但内部顺序、失败聚合和业务命令由官方代码固定。工作空间配方不得携带任意代码、文件路径、工具名、跨工位连线或通用 `module.run` 指令。新增插槽只能由第三条真实产线暴露出的重复需求推动，不能为假想扩展提前添加。

应用级能力仍必须支持当前 X、小红书和微信公众号及现有六种载荷。默认 AI 工作空间继续通过全部既有平台验收。UK 或自定义工作空间可以启用平台子集，但至少启用一个发布目标；停用平台阻止新方案选择该平台、新建该平台版本、发布动作和平台专属运行时，不删除历史内容和发布证据，也不启停按根隔离的通用 X Lists 情报输入。

## 8. 官方模板、工作空间配方与版本

AI 和 UK 是 WMB 随包的官方模板，不是两套产品。官方模板具有稳定 `template_id` 与 `template_version`。

每个工作空间只保存一个带 revision 的当前有效 `WorkspaceProfileV1`，字段限定为：

- 稳定 profile ID、revision 和可选官方模板 ID/版本；
- 显示名称、受众、内容目标和纯文本编辑简报；
- 情报包与创作包的 ID/版本；
- 启用的平台子集。

信源 URL、资料和内容属于工作空间业务数据，不塞入模块执行协议。能力包可以提供初始官方来源目录，后续来源仍通过既有 sources 业务命令管理。

工作空间配方只有一个提案确认过程；模块本身不另建通用确认状态。确认使用 expected revision 更新当前 profile。运行 profile-bound Agent task/job 时拒绝激活新配方，任务只需记录启动时的 workspace ID 与 profile revision。首期不建设多版本 pack runtime、旧包兼容或逐操作版本快照；官方更新仍只能提出可读差异，不能静默覆盖当前 profile。

## 9. AI 组装、WMB 校验、用户确认

工作空间模块化主要服务于 AI 和系统，而不是要求用户学习配置工具。

### 9.1 创建与修改

1. 用户在现有 Pi 或任意已接入的外部 Agent 中描述自媒体目标；
2. Agent 读取 WMB 官方模板、能力包目录和配置约束；
3. Agent 选择官方能力包并生成完整配方提案；
4. WMB 做确定性结构校验与依赖校验；
5. UI 展示人类可理解的结果单、相对当前版本的精确差异，以及新建工作空间将使用的数据目录；
6. 新建时由 UI 让用户选择或确认一个明确的空目录，用户再确认准确提案；
7. 已有活动根在单事务内更新 profile 后通过有界重启替换全部 profile-bound runtime 和 MCP URL；新根先幂等完成身份、schema 与 profile，再原子加入注册表，之后通过正常重启协议切换并完整读回。

用户以后可以用自然语言要求“增加签证政策内容”“暂停优惠信息”“让小红书表达更生活化”。Agent 只生成新提案，不直接改变有效配置。

WMB 不新增另一个“工作空间搭建聊天页”；请求继续走现有 Pi dock 或外部 Agent。

活动 MCP 只新增有限的应用级工具：列出工作空间、读取当前工作空间、列出官方模板/能力包，以及提交工作空间配方提案。读取当前工作空间与 UI、IPC、Pi 共用一个权威 workspace/capability snapshot，统一带出 workspace/data-root 身份、profile revision、能力包、发布平台子集和固定能力可用性，不在各入口重构第二份真相。其他资料、内容、发布和复盘工具仍只操作当前 MCP URL 所绑定的 data-root。应用级工具不能确认、激活、删除工作空间或传入任意文件系统路径；新 data-root 只能由 UI 选择和确认。

### 9.2 精确确认

未确认提案只保存在当前 Main 进程，重启后失效并要求 Agent 重新生成。确认必须绑定：

- 目标工作空间或新建工作空间提案 ID；
- 提案版本与规范化 hash；
- 基准有效 profile revision；
- 官方目录版本和所选能力包版本；
- UI 展示的完整规范化差异。

Agent 修改提案、基准版本变化、官方目录变化或 Main 重启都会让旧确认失效。Pi 和 MCP 可以读取与提交提案，但不能确认或激活；最终确认只由 UI 执行，并在消费时重新校验全部绑定内容。新根注册前崩溃不会改变当前 active；已完成身份初始化的候选根可按稳定 ID 重新关联。

缺少随包官方 Skill、工具或固定资源时阻止激活。缺少 API 凭证、模型选择或平台登录等人工前置时，可以在结果单明确列出待办后创建工作空间，但该能力保持可追踪的 `needs_user`，不得静默替换成其他模型、工具或账号。

### 9.3 无模型时的入口与生命周期

AI 与 UK 官方模板可以由 UI 直接创建，不依赖已经配置模型。AI 主要负责自定义赛道和后续改装。

用户可列出、重启式切换和移动后重新关联工作空间。重命名、归档、恢复和永久删除均后移。

WMB 的结构校验只接受能够表达受众、内容目标、固定创作产物和至少一个支持平台输出的自媒体配方。非自媒体目标返回不支持；WMB 不判断文案质量，也不声称理解了用户行业事实。

## 10. 应用级共享与业务隔离

应用级共享内容只包括：

- 工作空间注册表；
- WMB 官方模板与能力包定义；
- 应用版本、通用界面偏好和本机诊断。

资料、主题、方法结论、素材关系、账号、发布数据和业务知识绝不自动跨工作空间流动。AI 与 UK “互相回馈”只表示内核修复或经过 WMB 正式发布的官方能力包更新可供两者使用，不表示把一个赛道的资料或经验自动带入另一个赛道。

API/model 预设保存在当前 WMB 安装的用户目录并由所有工作空间共享；已有官方 AI 根预设在全局文件缺失时一次性迁移，旧根记录保留但不再作为真相源。浏览器配置、Pi 会话、小红书 cookies、平台账号和业务数据继续保存在各自 data-root，不隐式复制。

每个工作空间在每个平台仍最多保存一个活动账号，延续当前根内简单约束。不同工作空间可以拥有不同账号，因为其登录态和数据库天然分开；首期不提供同一工作空间内多账号管理，也不并发调度多个浏览器 profile。

## 11. 现有 AI 工作空间继续演进

AI 赛道不需要先开发完整，也不需要在产品上“封版”后才支持 UK。但工作空间改造不能与一个无法对账的脏基线并行实施。

当前 data-root 原地登记为 AI 工作空间：

1. 保留现有数据库、对象 ID、版本、关系、文件路径、哈希、Pi 会话、浏览器登录态和历史证据；
2. 只增加根身份和活动配方，不把现有 51 张业务/历史表改造成共享库多租户表；
3. 证明登记前后的 AI Today、Studio、Publish、Results、Knowledge、Pi 和 MCP 关键读回一致；
4. 继续开发 AI 赛道，每个新能力只判断属于固定内核还是 AI 官方能力包。

“AI 功能不中断”定义为：允许一次有界冷启动升级，升级后数据和已验收能力零回退；不承诺运行中的模型 turn 或浏览器动作跨版本存活。

正式实施前必须先完成当前基线审计：保护现有大量未提交改动，核对 `TASKS.md` 的完成/`needs_user` 事实，并让 `PLAN.md` 与已有 M-1700/M-1800 台账一致。新工作空间链必须依赖这个明确基线，不能与现有 AI 脏改动同时落地。

## 12. UK 工作空间与旧终端

UK 是第二个真实工作空间，不是新的 WMB 代码分支。

首轮创建一个全新 UK data-root，只复用：

- `uk-life-content-radar` Skill；
- UK 来源地图、分层信源和采集 SOP；
- 面向在英中国人的受众、主题和核验规则；
- WMB 已有的资料、选题、内容、发布和 Agent 业务能力。

AI 情报 runner 当前写死的 Skill、AI 路线和固定 AI List 必须改为按活动工作空间已批准配方选择。X Lists 本身是所有自媒体工作空间共享、按 data-root 隔离的信源能力；UK 可使用本根用户明确启用的 List，但不能继承 AI 的 `AI前沿`、AI List 选择策略、AI source-index/wire 或 AI 来源路线。UK 验收放置 AI-only sentinel 证明这些专属路线零调用。具体调用继续遵守 SPEC CAP-017 的 current workspace/root/account/binding 逐次校验，不另造协议。

旧 UK 终端不进入首轮关键路径，也不自动删除。UK 新根跑通后，再对旧终端做只读能力/数据清单和 must-preserve/gap 矩阵。旧终端中的 approvals、packages、semantic vectors、产品策略、leads、deals 等 WMB 当前范围外对象不得为了合并而扩张 WMB；只对双方已有明确映射的资料、内容和素材另立可选导入计划。

## 13. 文字、图片和视频边界

自媒体创作是固定核心，文字、图片和视频是同一内容项目的不同创作产物。长期方向是让 WMB 管理创作目标、上下文、生成请求、版本、素材关系、选择、平台组装和结果复盘。

图片和视频的生成、局部修改或专业编辑优先调用外部模型、MCP 或专业工具。WMB 不自研 Photoshop/Premiere 类编辑内核。

多模态生成不是当前工作空间化改造的主线。首轮不提前建设媒体 provider 抽象、通用生成协议或新编辑器。

## 14. 错误与失败原则

- `WORKSPACE_BUSY`：当前存在不可安全切换的任务或外部写入；
- `WORKSPACE_NOT_FOUND`：注册表或目标根不存在；
- `WORKSPACE_ID_MISMATCH`：注册表与根内身份不一致；
- `WORKSPACE_SWITCH_FAILED`：目标启动失败，恢复原活动根；
- `PROFILE_STALE`：确认绑定的基准配方、提案或官方目录已变化；
- `OFFICIAL_PACK_UNAVAILABLE`：提案引用的官方能力包或随包资源不存在；
- `needs_user`：缺少 API、模型、登录态或其他明确人工前置；
- 未确认提案：只在当前 Main 会话有效，重启后旧确认返回 `PROFILE_STALE`；
- 旧 MCP URL：切换后关闭并拒绝请求，绝不转发到新工作空间；
- 非活动工作空间任务：不后台执行，激活后按既有恢复规则处理；
- AI 生成质量：WMB 只验证结构、模块、引用和状态，不伪称内容判断正确；
- 发布与平台写入：继续遵守准确账号、内容版本、素材和精确变更绑定的人工确认。

失败、拒绝或过期的配方提案不改变当前有效 revision。切换失败不修改目标或原工作空间的内容业务对象；事务性 schema/migration 元数据和诊断日志是唯一允许差异。

## 15. 演进顺序与阶段 Gate

以下是产品级依赖顺序；可执行的唯一状态仍以正式 `TASKS.md` 中 WMB-1900～WMB-1912 为准。

### 阶段 A：收口真实基线

- 只读盘点当前 Git 改动、正式 data-root、任务台账和现有验收收据；
- 将未实际完成的外部登录/人工验收保持 `needs_user` 或 blocked，不以历史命令成功替代；
- 让 PLAN 与唯一 TASKS 状态一致；
- 封存 Git HEAD、脏 diff/untracked 归属、验收脚本与包 hash、稳定业务投影、资产/导出 hash、登录读回和 Pi 会话，并列出只允许 workspace/profile/migration 元数据与运行日志变化的白名单。

Gate：当前改动得到归属或独立提交，AI 基线可重复读回，没有并行 `doing` 工作。

### 阶段 B：注册表与默认 AI 工作空间

- 将现有 data-root 零搬迁登记为 AI 工作空间；
- 增加工作空间列表、身份核对、移动后重新关联和单活动根切换；
- 用 mutation drain、持久切换日志与 Electron relaunch 实现旧 MCP/进程失效和崩溃回滚，不做进程内运行时重绑。

Gate：AI 根对象、ID、版本、文件和现有业务读回不变；运行任务时切换稳定失败；空闲切换和冷重启不串线。

### 阶段 C：AI/UK 两个编译期官方模板

- 创建全新 UK data-root；
- 先用两个固定 profile 分支选择 AI 或 UK Skill、来源路线和平台偏好；
- 盘点所有 AI-only dispatcher ID，并在共同边界设置可读回 sentinel；X Lists 保持共享，但账号、绑定、缓存、操作和 source feed 全部根内隔离；
- 通过 UI、Pi 与外部 MCP 跑通 UK 资料 → 方案 → 内容 → X 纯文字平台版本；
- 使用相同 URL、日期、主题和素材 hash 验证两个根天然隔离。

Gate：UK sentinel 证明零调用 AI Skill、固定 AI List、AI source-index/wire 和 AI 来源路线；AI 全部既有验收继续通过；UK 的通用 X Lists 只读写本根；非活动根无后台进程或写入。

### 阶段 D：从两条真实产线提取最小官方目录

- 只提取 AI 与 UK 已经出现的真实交换点；
- 固定情报包、创作包和平台子集；复盘仍留在固定内核；
- 定义有限字段的 `WorkspaceProfileV1`，任务只记录 profile revision；
- 不建设动态加载、依赖图或通用执行器。

Gate：AI/UK 用户可见结果不因抽取而变化；同一固定业务命令仍由 UI、Pi 和外部 Agent 共用。

### 阶段 E：AI 创建与改装工作空间

- 让 Pi/MCP 读取官方目录并提交配方提案；
- 提案仅会话有效，实现完整结果单、精确 diff、每个绑定字段的过期确认拒绝和 UI-only 激活；
- 由 Owner 提供第三赛道目标并在真实 UI 手动确认，再完成冷重启和相互引用的 X 纯文字内容闭环。

Gate：AI 不能激活配方；无效/过期提案零写入；非自媒体目标无法形成合法自媒体配方。

旧 UK 数据导入、图片/视频生成能力及更多官方能力包均不属于本阶段；只能在上述主线稳定后按真实需求另立计划。

## 16. 业务验收

### 16.1 AI 原地登记

- 封存 manifest 绑定实现/验收器 hash；登记前后稳定业务投影、对象 ID/revision、资产与导出 hash 一致，只允许声明过的 workspace/profile/migration 元数据和运行日志变化；
- 当前 AI data-root、浏览器登录态、Pi 会话和小红书 runtime 不被移动或清空；
- AI Today、Studio、Publish、Results、Knowledge、Pi/MCP 关键读回语义一致；
- 默认 AI 工作空间继续通过当前三平台和六种载荷验收。

### 16.2 切换与隔离

- AI 与 UK 可分别保存相同 URL、日期、主题、平台账号和素材 hash；
- 两个工作空间的资料、内容、任务、失败、账号、指标和方法结论互不可见；
- 有运行任务、外部写入或无法排空的 mutation 时切换返回 `WORKSPACE_BUSY`；
- 空闲切换重启应用，关闭旧 MCP URL、HTTP stream/session 和完整进程树，外部 Agent 只能通过新 URL 连接并读回准确工作空间；
- 在切换日志每个阶段注入失败或强杀进程，冷开均恢复 previous；移动根目录后按稳定 ID 重新关联，错误 ID 被拒绝；
- 非活动根跨越 job due 时间的 DB/WAL、文件、revision 和进程/端口保持不变；切回后安全 job 只恢复一次，不安全 job 不重放。

### 16.3 UK 第二产线

- UK 官方信源经过 UK Skill 进入 UK 资料库；
- Agent 基于 UK 资料生成相互引用的方案、内容项目和 X 纯文字平台版本；
- 所有已盘点 AI-only Skill、固定 AI List/策略、来源与创作入口在 UK 的 UI、Pi、外部 MCP 路径中零调用、零写入；
- UK 的通用 `x_lists.*` 工具使用本根独立登录态、绑定和缓存，可将本根启用 List 的帖子写入 UK 资料库，但不得读取 AI 根的账号、List、缓存或 feed；
- UI、Pi 与外部 Agent 从同一根绑定业务 API 读回完整 UK 链路。

### 16.4 AI 组装与人工确认

- Agent 只能使用 WMB 返回的官方能力包 ID、版本和配置字段生成提案；
- 缺失官方资源、无效配置和过期提案在激活前被拒绝；
- UI 显示完整结果和相对当前有效版本的精确差异；
- Pi/MCP 无法确认或激活；
- 未确认提案只在当前 Main 会话有效；每个 hash/base/catalog/pack/platform/diff 绑定变化都使确认失效且零写入；
- 已有活动根确认单事务更新 profile revision 后冷重启并替换旧 runtime/MCP URL；新根先完整初始化再加入注册表，冷重启读回同一 revision；
- 新根初始化中断不创建 registry/active 条目，候选根可按稳定身份安全重验；
- 拒绝、失败或过期确认不改变当前有效配方或 active；
- Owner 提供并已在真实 UI 手动确认第三赛道“游戏资讯”，随后走完相互引用的资料 → 方案 → 内容 → X 纯文字平台版本；其通用 X Lists 只使用游戏资讯根的登录态、绑定、缓存和 source feed；
- 非自媒体目标因缺少固定自媒体输出合同而无法激活。

## 17. 对抗性审计与主审裁决

本设计先后由两轮、共六个互不共享中间结论的审查者从产品边界、迁移隔离、最小交付、追踪关系和失败路径审计。主审没有按多数票决策，而是回到现有 data-root、SQLite schema、运行时单例和 UK 实际数据模型逐项核对。

| 审计发现 | 主审裁决 |
| --- | --- |
| 共享数据库工作空间化会重建大量唯一键、外键、JSON resolver 和幂等账本 | 接受反例；改为一个 data-root 一个工作空间，不做共享库多租户化 |
| Pi、MCP、Browser、XHS 是单例，进程内重绑会横切全部 IPC/事件 | 采用单活动工作空间、mutation drain 与 Electron relaunch；不实现 renderer epoch |
| 原“官方模块”契约接近类型化工作流引擎 | 收窄为有限 `WorkspaceProfileV1`、情报/创作两个编译期能力包和平台子集，无通用执行器 |
| 浏览器/Profile 隔离会暗中引入并行多账号调度 | Profile 随 data-root 隔离，但首期只运行一个 root；不做并行多账号调度 |
| AI“不中断”无法按字面零停机 | 明确定义为一次有界冷升级后数据与能力零回退 |
| 运行中任务、迟到请求可能写入或显示在新空间 | 忙态门禁与 mutation drain 后整应用重启，旧 renderer、连接和进程全部销毁 |
| 官方升级可能诱发多版本运行时和全操作快照 | 首期仅一个 effective profile revision，任务记录该 revision，运行时禁止激活 |
| 工作空间创建只有 AI 入口会卡住未配置模型的新用户 | AI/UK 官方模板支持 UI 直接创建；AI 用于自定义和改装 |
| 启用平台子集可能削弱现有三平台合同 | 应用与默认 AI 保留全部现有平台验收；其他空间至少启用一个平台 |
| 把 X Lists 当作 AI-only 会让 UK/游戏失去重要通用信源 | 将 X Lists 固定为所有自媒体根共享的输入能力，与发布平台子集解耦；AI 固定 List、AI source-index/wire 仍留在 AI pack，所有账号与缓存按根隔离 |
| 旧 UK 数据迁移会把 CRM/经营范围带入 WMB | 从首轮关键路径删除；新 UK 根先验收，旧数据另立可选映射计划 |
| 当前脏工作区和 PLAN/TASKS 漂移使回归基线不可判定 | 将真实基线收口设为所有实施前的独立 Gate |
| 配方确认可能激活 Agent 后改写的内容 | 确认绑定提案 revision/hash、基准版本、目录版本和完整 diff，并在消费时重验 |
| 新根提案持久化会造成应用级/根内双重存储和伪原子事务 | 未确认提案只在 Main 会话存在；新根完整初始化后才进入注册表 |
| `review_pack` 和工作空间归档等尚无真实需求 | 保留固定复盘内核，只交付列表/切换/重关联；有证据后再扩 |
| 十一个顺序任务包含纯内部抽象任务 | 压缩为八项，把目录提取与首个真实消费者合并 |

审计后的剩余风险是：data-root 隔离牺牲了跨工作空间同时运行和统一搜索。该能力不是用户当前目标，也没有真实验收需求；只有未来出现必须跨空间并发或搜索的证据时，才重新评估共享索引或多运行时，而不是现在预建。

## 18. 成功判断

本次产品演进成功，不以“出现一个工作空间切换器”判断，而以以下事实同时成立判断：

1. 现有 AI data-root 零业务搬迁，AI 赛道可以继续开发；
2. UK 不再需要独立开发另一套自媒体终端；
3. AI 与 UK 共享同一 WMB 代码和业务内核，但数据库、素材、登录态和业务知识互不混淆；
4. Agent 能用官方能力包形成结构化、可读回的赛道提案；
5. 用户只负责目标、价值判断和最终启用确认，不需要手工搭建生产线；
6. 新赛道通过创建新 data-root 和配方完成，不复制 WMB 应用，也不重建现有业务 schema；
7. 产品仍然是清晰的自媒体创作终端，而不是通用工作流或插件平台。
