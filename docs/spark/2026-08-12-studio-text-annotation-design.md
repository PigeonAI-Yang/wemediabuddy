# Studio 正文问题标记与 Pi 批注上下文设计

- 日期：2026-08-12
- 状态：Owner 已批准定稿，WMB-5207 实施中
- 范围：创作项目核心正文及可编辑的平台版本正文

## 1. 问题与目标

用户让 Pi 写好正文后，可能只感觉某句话“不对劲”，但暂时说不清原因。当前创作编辑器只能直接改字或向 Pi 重新描述位置，不能把具体文字可靠地指出来。

本功能允许用户拖选连续文字，通过右键创建“仅标记”或“标记并说明”批注。批注独立于正文保存；创建时不调用 Pi。用户之后向 Pi 发消息时，当前工作稿与全部未解决批注自动进入结构化上下文，使“把我标出来的地方改顺一点”成为完整指令。

成功状态：

1. 用户可以低成本指出具体文字，即使尚不能说明原因。
2. 标记在正文中清晰可辨，但不会表达“删除”或“事实错误”的错误语义。
3. 标记不污染 Markdown、平台正文、复制内容、版本比较或发布载荷。
4. Pi 能可靠取得当前工作稿、被标文字、邻近上下文和可选说明。
5. 正文变化后，标记只在可以可靠定位时继续存在；宁可自动解决，也不错误挂靠。

## 2. 非目标

首期不包含：

- 创建批注后自动调用 Pi 或自动改稿；
- 多人协作、批注作者权限或实时同步；
- 批注回复线程、@提及、审核流；
- 预设问题分类体系；
- 标题、只读历史版本或实时预览上的批注；
- 将批注编码进 Markdown 自定义语法；
- 跨项目批量批注管理。

## 3. 已选方案与备选方案

### 3.1 已选：独立批注层

正文和批注分别持久化。批注保存文档范围、字符区间、原文、前后文锚点、可选说明及状态。编辑器将批注投影为视觉装饰，Pi 上下文生成器将其序列化为结构化数据。

选择原因：正文保持干净；批注可以迁移、解决和审计；复制、平台适配和发布无需清理隐藏符号；Pi 不会把标记字符误当成正文。

### 3.2 未选：Markdown 内嵌标记

优点是实现直接，范围天然随文字移动。缺点是污染原稿、复制内容、版本差异及平台版本，并可能被 Pi 或发布流程解释为正文。拒绝。

### 3.3 未选：仅右侧行级批注

优点是正文视觉更轻。缺点是无法准确表达“这几个词不舒服”，仍需锚点模型，且用户回看成本更高。右侧列表只作为独立批注层的辅助视图，不代替正文高亮。

## 4. 用户交互

### 4.1 创建批注

1. 用户在当前可编辑正文中按住鼠标并拖选任意连续、非空白文字。
2. 用户右键，编辑器打开应用内上下文菜单，而不是依赖操作系统默认菜单。
3. 菜单提供：
   - `标记为有问题`
   - `标记并说明…`
4. `标记为有问题`立即创建无说明批注。
5. `标记并说明…`打开紧邻选区或指针位置的紧凑输入层。用户输入自由文本说明后确认；取消不创建批注。
6. 创建成功后正文立即显示标记，右侧未解决数量增加。焦点回到正文，用户可继续阅读或标记下一处。
7. 创建动作不展开 Pi、不发送消息、不启动任务，也不改写正文。

空选区或纯空白选区不显示两个批注动作。跨段连续选择允许。选择范围与任何未解决批注重叠时拒绝创建，并提示“所选文字已有问题标记，请先编辑或移除原标记”。首期不合并或嵌套标记。

### 4.2 操作已有批注

右键或点击已有标记后提供：

- `添加说明…`或`编辑说明…`
- `移除标记`

点击正文中的标记会选中对应批注卡并打开批注页签。点击批注卡会滚动到对应文字，并短暂加强高亮。移除标记属于用户主动解决，记录解决原因，不删除历史记录。

### 4.3 正文视觉

标记不能使用删除线或高饱和红色，以免被理解为“已删除”或“事实错误”。

- 所有未解决批注：低饱和暖黄色底纹。
- 仅标记：琥珀色点状下划线。
- 标记并说明：琥珀色实线下划线，文字末端附一个不占正文排版宽度的小批注点。
- 悬停、键盘聚焦或选中批注：底纹适度加深。
- 跨行标记：只装饰实际被选文字，不铺满整行。
- 白昼与黑夜主题分别提供对比度合格的背景、下划线、聚焦轮廓和批注点 token。
- `prefers-reduced-motion: reduce` 下，定位时不平滑滚动，聚焦提示不使用动画。

富文本模式直接在渲染 DOM 上投影装饰；源码模式使用与 textarea 文本、滚动、字号和换行几何同步的装饰层。任何模式都不得向正文字符串插入标记语法。

## 5. 批注面板

复用当前右侧版本侧栏，在顶部增加两个页签：

- `批注 N`：N 为当前文档范围的未解决批注数；
- `版本 M`：保留现有核心正文或平台版本列表。

默认规则：当前文档存在未解决批注时，创建首条批注后切到“批注”；之后尊重用户最后选择的页签。没有批注时仍可进入空状态。

每张未解决批注卡显示：

- 被标记原文，超长时折叠但可展开；
- 用户说明；无说明时显示“仅标记”；
- 所属文档：核心正文或具体平台版本；
- 创建时间；
- `编辑说明`和`移除标记`操作。

面板底部有折叠的“已解决”区域，显示原文、原说明、解决原因和解决时间。已解决批注可手动重新打开；重新打开前必须在当前正文中唯一定位原文与上下文，否则拒绝并提示重新选择文字创建标记。

工具栏或右侧入口应显示未解决数量，例如`批注 · 3`。批注面板提供`和 Pi 讨论这 3 处`按钮；按钮只展开 Pi 面板并聚焦输入框，不自动填入命令、不自动发送。

## 6. 数据模型

新增独立的正文批注实体。字段语义如下：

```text
id
projectId
documentKind: core | platform
documentId: 当前核心内容版本锚点或平台版本 ID
platform: x | xiaohongshu | wechat | null
startOffset
endOffset
quotedText
prefixContext
suffixContext
bodyFingerprint
note: string | null
status: open | resolved
resolvedReason: edited | deleted | ambiguous | user_removed | null
createdAt
updatedAt
resolvedAt
revision
```

约束：

- `startOffset < endOffset`，且 `quotedText` 必须等于创建时正文的对应区间。
- `note` 去除首尾空白后为空则保存为 `null`。
- 同一文档范围内，未解决批注区间不得重叠。
- `documentKind=core` 时 `platform=null`；`documentKind=platform` 时必须有平台和平台版本 ID。
- 批注的并发更新采用 `expectedRevision`，冲突返回当前记录，不静默覆盖。
- 项目硬删除时批注随项目删除；项目归档不解决或删除批注。

核心正文尚未保存的本地工作稿仍允许创建批注。此时 `documentId` 指向其基准核心版本，`bodyFingerprint`和锚点针对当前工作稿。批注立即持久化；工作稿正文仍沿用现有保存语义，不因创建批注而暗中创建正文版本。

## 7. 锚点与生命周期

### 7.1 编辑器内增量更新

正文每次发生可识别的文本替换时，以最长公共前后缀确定单一变更区间：

- 变更完全发生在标记之前：按净字符变化量移动起止位置。
- 变更完全发生在标记之后：位置不变。
- 变更与标记内部或边界相交：立即将该批注标记为`resolved`，原因为`edited`；正文装饰消失。

一次变更可能影响多个批注，各批注独立计算。更新后的开放批注必须再次满足原文与范围一致性。

### 7.2 保存与外部正文替换

保存核心正文形成新版本、保存平台正文形成新修订时，批注迁移与正文保存处于同一事务。新正文若来自当前编辑器增量路径，采用已更新范围；若来自 Pi、其他窗口或外部业务命令，则执行保守重定位：

1. 在新正文中查找`quotedText`的所有精确匹配。
2. 使用`prefixContext`、`suffixContext`和距原位置的偏差筛选。
3. 只有一个候选满足锚点约束时迁移。
4. 原文不存在时，以`deleted`解决。
5. 存在多个合理候选或无法唯一判断时，以`ambiguous`解决。

禁止采用可能把批注挂到另一句的模糊字符串猜测。原则：宁可不显示，也不挂错句子。

### 7.3 未保存正文丢失

应用重开、项目重载或外部更新使未保存工作稿消失时，按保守重定位规则在当前权威正文中恢复。不能唯一恢复的批注进入已解决，不产生悬空高亮。

## 8. Pi 上下文交接

创建或编辑批注本身只写业务状态，不调用 Pi。

当用户位于创作项目页面并主动向 Pi 发送下一条消息时，页面上下文必须使用当前正在编辑的文档，而不是无条件使用上次保存版本。上下文包括：

```text
studioDocument
- projectId
- documentKind
- documentId / baselineVersionId
- platform
- title
- currentBody
- bodyFingerprint
- dirty

openAnnotations[]
- annotationId
- startOffset
- endOffset
- quotedText
- prefixContext
- suffixContext
- note
```

Pi 面板在发送前明确显示`已带入 N 条正文批注`。用户可发送“把我标出来的地方改顺一点”等自然语言。Pi 仍须以用户消息作为执行意图；批注存在本身不构成改稿授权。

上下文预算不足时按以下优先级裁剪：

1. 所有未解决批注的原文和用户说明；
2. 每条批注邻近上下文；
3. 标题和文档身份；
4. 未标记正文的远端部分。

不得丢弃部分批注而仍显示完整批注计数。若硬性上限导致无法带入全部批注，发送前明确显示实际带入数与省略数。

Pi 或其他业务命令写回正文后，使用第 7.2 节规则迁移或解决批注。

## 9. 组件与接口边界

实现应保持以下职责分离：

1. **选区捕获与菜单控制器**：把富文本 DOM Range 或源码 textarea 选区统一转换为正文字符区间；负责右键菜单与说明输入层，不负责持久化算法。
2. **批注锚点服务**：验证区间、计算增量迁移、执行外部正文保守重定位。使用纯函数，可用固定文本独立验证。
3. **批注存储服务**：创建、更新说明、解决、重新打开、按文档列举；负责事务和 revision 冲突。
4. **正文装饰层**：只接收正文及开放批注并渲染；不拥有业务状态。
5. **批注侧栏**：显示开放/已解决记录并发出业务命令。
6. **Studio Pi 上下文适配器**：从当前编辑状态和开放批注生成结构化上下文；不触发发送。

现有核心正文与平台版本的保存入口必须统一调用批注迁移服务，不能为 UI 保存和 Pi 写回建立两套迁移规则。

## 10. 错误处理与一致性

- 创建失败：不显示临时高亮，保留文字选区并显示可重试错误。
- 编辑说明失败：保留旧说明和现有高亮。
- 移除失败：批注继续保持开放。
- revision 冲突：重新读取当前批注并提示其已在其他位置更新。
- 正文保存成功但批注迁移失败：整个事务回滚；不得产生正文已变、批注仍指旧范围的部分成功。
- 装饰层发现`quotedText`与当前范围不一致：不渲染该高亮，触发权威重定位或解决流程，不在前端自行猜测。
- 当前正文为空或选区超出边界：拒绝创建并返回验证错误。
- Pi 上下文生成失败：阻止带有错误上下文的发送并显示原因；不得悄悄退化为不带批注。

## 11. 可访问性与键盘行为

右键是主要入口，但不能成为唯一入口：选中文字后，格式工具栏提供等价的`标记`按钮；键盘用户可通过工具栏完成“仅标记”，并从打开的菜单选择“标记并说明”。

正文标记除颜色外还使用点状/实线下划线区分。批注装饰具有可聚焦语义和可读标签，例如“问题标记：仅标记”或“问题标记：太营销”。批注菜单、输入层和侧栏遵循焦点陷阱、Escape 关闭及焦点返回规则。

## 12. 验收标准

1. 富文本和源码模式均可拖选连续文字，通过右键创建“仅标记”或“标记并说明”。
2. 键盘用户可通过格式工具栏完成同等操作。
3. 两种标记样式可区分；跨行高亮只覆盖选中文字，白昼/黑夜及 reduced-motion 行为正确。
4. 点击正文标记与批注卡可双向定位；侧栏准确显示开放和已解决数量。
5. 切换富文本/源码模式、关闭并重新打开项目后，未解决批注仍定位到正确文字。
6. 在标记之前编辑时范围随净字符量移动；在标记内部或跨边界编辑时立即自动解决。
7. 多个相同句子、整篇改写、外部更新及 Pi 写回时，只迁移唯一可靠匹配；不存在错误挂靠。
8. 核心正文与每个平台版本的批注彼此隔离，不串到其他页签或版本。
9. 当前工作稿未保存时仍可批注；应用重开后无法可靠恢复的批注进入已解决。
10. 创建批注不打开 Pi、不发送消息、不启动任务；`和 Pi 讨论`只聚焦输入框。
11. 用户主动发送消息时，Pi 收到当前工作稿和结构化未解决批注，界面显示实际带入数量。
12. Pi 上下文超限时优先保留全部批注；无法全部带入时发送前明确告知省略数量。
13. 保存正文与迁移批注原子完成；任何迁移失败不产生部分成功。
14. 复制正文、保存版本、创建平台版本、版本比较和发布载荷均不包含批注语法或视觉字符。
15. 创建、编辑说明、移除、冲突和重定位失败时均无假高亮、悬空标记或静默丢失。
