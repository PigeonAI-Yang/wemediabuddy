# 项目专项调查与事实驱动写作流程设计

日期：2026-08-16  
状态：Owner 已确认产品方向，书面规格已自检，待 Owner 复核  
范围：选题进入创作项目后，从调查提纲、记者专项调查、主管重判到写手完成正文的完整业务流程

## 1. 决策摘要

当 Owner 决定把一篇稿件认真写完整时，创作项目不得直接从初步选题进入写手起草。主管必须先阅读当前选题、正文、已有来源与批注，拟定调查提纲并呈报 Owner。Owner 确认调查范围后，主管才可派记者围绕该项目进行全面、深入的专项调查。

调查不服务于证明既定观点。原始选题、核心判断和表达角度都是调查前假设，必须允许被新增事实修正、收窄、推翻或判定不值得继续。记者对事实负责，不对原角度负责。

记者交付调查资料包后，主管基于全部最新材料重新判断本稿应当写什么，并把“调查结果与新写作方向”再次呈报 Owner。只有 Owner 确认调查后的写作方向，主管才可派写手完成正文。

正式主链：

```text
原始情报
→ 暂定选题
→ 创作项目
→ 主管拟调查提纲
→ Owner 确认调查范围
→ 记者专项调查
→ 主管验收并重新判断选题
→ Owner 确认调查后的写作方向
→ 写手完成正文
→ 审稿 / 平台版本 / 发布 / 复盘
```

## 2. 认识论原则

1. **选题是调查起点，不是调查结论。**
2. **调查服从事实，不服从原选题角度。**
3. **记者负责扩大事实覆盖、核验来源、呈现冲突与未知，不负责维护某个观点。**
4. **主管负责把调查材料综合成可供 Owner 决策的认识，不得把记者交付的一堆链接直接转交写手。**
5. **写手依据调查后经 Owner 确认的写作方向写作，不得把调查前假设冒充已确认事实。**
6. **允许最有价值的调查结果是：原角度被推翻、选题被放弃，或者出现更好的新角度。**
7. **无法确认的内容必须保持未知，不得为使稿件完整而补造结论。**

## 3. 各业务对象的职责边界

### 3.1 原始情报 / 发现

职责：广泛、低成本地发现外部变化和潜在线索。

产物：原始来源、简要摘要、初步时效与机会信号。

非职责：全面理解某一问题；形成完整证据体系；替具体稿件完成事实调查。

### 3.2 选题

职责：提出一个值得投入调查和表达的问题。

选题保留调查前快照：

- 为什么当时值得关注；
- 关联哪些原始情报；
- 初步受众价值；
- 初步核心判断与表达角度；
- 当前已知和明显缺口。

选题快照不得在调查后被覆盖。调查结束后应追加结果：成立、收窄、改向、推翻或放弃，以便复盘认识变化。

### 3.3 主题

职责：承载长期认识对象，汇聚多次调查、稿件、资料与复盘形成的可复用知识。

主题不承载某次记者工单，不替代某篇稿件的调查档案。专项调查结束并经主管验收后，具有长期价值的事实、争议、时间线与待研究问题才可沉淀到主题。

### 3.4 创作项目

职责：作为“本次具体稿件”的唯一工作主线。

一个创作项目串联：

```text
调查前选题快照
→ 调查提纲及审批
→ 专项调查轮次
→ 调查资料包
→ 调查后写作方向及审批
→ 正文及版本
→ 平台版本
→ 发布记录
→ 复盘
```

专项调查的主档案必须挂在创作项目下。第一阶段只支持项目级专项调查；如果 Owner 希望“先调查再决定是否写”，系统仍创建一个处于“调查中”的创作项目，而不再建立第二套选题级调查协议。

### 3.5 资料库

职责：保存可复用、可追溯的材料事实，包括原始内容、来源身份、获取时间、原始链接、本地归档、核验状态及实体关联。

记者发现的新来源必须先进入资料库，再关联本次调查与创作项目。资料库不保存本次调查的任务进度、主管综合判断或写作方向。

原则：**资料库存材料；创作项目存本次如何调查、如何理解、如何形成文章。**

### 3.6 智能体 / 工单

职责：展示谁在执行、进度、阻塞、运行记录和交付状态。

记者工单必须引用 `projectId` 和专项调查标识。智能体页是运行投影，不是调查成果的权威存储。工单 transcript 关闭后，调查提纲、来源关联、调查资料包和主管综合判断仍必须在创作项目中完整存在。

## 4. 创作项目内的信息架构

创作项目提供三个相互关联但职责不同的工作面：

### 4.1 调查

- 调查前选题快照；
- 主管拟定的调查提纲；
- Owner 的修改、确认或驳回；
- 当前专项调查状态；
- 记者覆盖进度与阻塞；
- 调查资料包；
- 冲突事实、未知项与未解决问题；
- 主管的调查后综合判断；
- Owner 确认后的写作方向。

### 4.2 正文

- 当前正文；
- 写作批注；
- 写手交付；
- 版本历史；
- 审稿修改。

### 4.3 来源

- 本稿关联的全部资料；
- 每份资料对应的调查问题；
- 一手、二手、数据、案例、反例、背景或不同立场等用途；
- 核验状态与引用状态；
- 来源之间的冲突关系。

不新增“专项调查”一级导航。调查服务于具体稿件，必须留在创作项目上下文中。Today、选题和智能体页只显示状态摘要与进入该项目的入口，不复制完整内容。

## 5. 调查提纲

主管收到“把这篇写完整”后，先读取：

- 调查前选题快照；
- 当前正文和版本；
- 已关联来源；
- 相关主题中的既有认识；
- 当前批注；
- 目标受众、内容目标和编辑简报。

主管生成的调查提纲必须包含：

1. **调查对象与边界**：这次具体要弄清什么，暂不调查什么；
2. **当前已知**：已有资料能够确认的事实；
3. **当前假设**：尚未证实的判断、推测和二手说法；
4. **核心调查问题**：按问题组织，而非按预定文章章节组织；
5. **事实维度**：背景、时间线、机制、参与方、利益关系、数据与影响；
6. **材料要求**：一手文件、原始数据、案例、反例、历史对照与不同立场；
7. **真实性风险**：高风险主张、口径歧义、可能过时或无法确认的内容；
8. **推翻条件**：哪些发现会迫使原选题收窄、改向或放弃；
9. **完成标准**：何时可认为覆盖充分，哪些未知允许保留。

提纲是调查地图，不是文章提纲，也不是结论清单。

Owner 可以修改、增删、确认或驳回。未获得 Owner 对当前提纲版本的明确确认，主管不得派记者开工。确认后保存不可变审批快照；后续修改形成新版本，不覆盖旧版本。

## 6. 记者专项调查

### 6.1 工单输入

记者收到：

- 项目身份；
- 经 Owner 确认的调查提纲版本；
- 已有关联资料；
- 相关主题上下文；
- 允许访问的渠道和工具；
- 调查完成标准。

记者不接收“必须证明的结论”。调查前角度只能作为来源背景并明确标记为暂定假设。

### 6.2 调查行为

记者应当：

- 优先寻找一手来源并保留原始出处；
- 补齐背景和时间线；
- 检查数据口径、时间范围与样本限制；
- 寻找典型案例、反例和失败案例；
- 收集利益相关方的不同立场；
- 区分事实、主张、推测、宣传与评论；
- 标记来源间冲突和无法确认的信息；
- 主动寻找能够推翻当前理解的材料；
- 发现与调查对象直接相关的新方向时继续追踪，并在资料包中解释扩展原因。

记者可在已确认的调查对象内扩展问题，不必为每条新线索再次请求批准；如果发现需要改变调查对象、显著扩大边界或转向另一选题，工单进入 `needs_user`，由主管呈报 Owner 决定是否修订提纲。

### 6.3 调查资料包

记者交付物不是链接集合，而是按调查问题组织的结构化资料包：

1. 调查范围与实际覆盖；
2. 事实和时间线；
3. 原始来源及其用途；
4. 数据、案例与反例；
5. 各方观点及依据；
6. 冲突信息；
7. 已确认、较可信、尚不确定、无法确认的内容；
8. 新发现的问题和方向；
9. 原调查提纲尚未完成的部分；
10. 原选题角度受到的事实影响，但记者不替主管决定最终文章立场。

资料包中的重要事实必须能回指资料库中的来源记录。没有来源关联的事实只能标记为待核验，不得进入已确认事实。

## 7. 主管验收与调查后重判

记者交付后，主管不得直接派写手。主管先验收：

- 调查提纲是否逐项得到回应；
- 来源是否可追溯；
- 一手资料是否充分；
- 反例和不同立场是否被覆盖；
- 冲突和未知是否诚实保留；
- 是否存在影响核心理解的缺口。

验收结果：

- **通过**：进入调查后重判；
- **需要补查**：按原提纲要求记者补充，不需要 Owner 重批；
- **需要扩展范围**：形成提纲新版本，回到 Owner 审批；
- **无法继续**：呈报真实阻塞或材料不足，禁止伪装完成。

主管随后形成“调查结果与新写作方向”，内容包括：

1. 调查后最重要的事实；
2. 哪些调查前判断成立；
3. 哪些需要收窄、修改或推翻；
4. 调查中新出现的关键观察；
5. 仍然存在的未知和表达边界；
6. 建议结果：继续原角度、调整角度、采用新角度或停止写作；
7. 如果继续，新的核心问题、受众价值、文章范围和写作约束。

## 8. 第二次 Owner 审批与写手启动

两次审批回答不同问题：

- 第一次审批：“这件事是否值得按此范围投入调查？”
- 第二次审批：“调查之后，我们究竟应该写什么？”

无论原角度是否变化，调查后的写作方向都必须呈报 Owner。Owner 可以确认、修改、要求补查或停止项目。

只有当前写作方向获得明确确认，项目才能进入 `ready_to_write`，主管才能派写手。写手输入为：

- 经确认的调查后写作方向；
- 调查资料包；
- 可追溯来源；
- 当前正文与批注；
- 受众和平台约束。

写手若在写作中发现事实缺口，不得自行补造或把推测写成事实；应把项目退回“需要补查”，由主管决定补派记者。

## 9. 状态模型

每个创作项目同一时刻最多有一个活动专项调查轮次。项目调查阶段采用：

```text
outline_pending_approval
→ researching
→ research_review
→ direction_pending_approval
→ ready_to_write
→ writing
→ completed
```

分支状态：

- `outline_rejected`：Owner 驳回调查提纲；
- `needs_user`：范围变化、关键访问阻塞或主管无法自行决策；
- `needs_more_research`：主管验收后要求按已确认范围补查；
- `abandoned`：调查结果表明不值得继续，或 Owner 停止项目；
- `failed`：执行失败且无可用交付。

所有审批、状态转换和调查轮次必须可追溯。补查发生在同一调查轮次；Owner 确认改变调查对象或显著扩大范围时创建新提纲版本。已确认版本、既有资料包和原写作方向不得被覆盖。

## 10. 数据归属与去重原则

| 信息 | 权威归属 | 其他页面如何使用 |
| --- | --- | --- |
| 原始来源正文、链接、归档、来源身份 | 资料库 | 项目、主题和调查只引用来源 ID |
| 调查前选题判断 | 选题快照 | 创作项目只读保留起点 |
| 调查提纲、审批、资料包、调查后判断 | 创作项目专项调查 | 智能体与 Today 仅投影状态摘要 |
| 记者运行记录、进度、阻塞 | 智能体工单 | 创作项目显示必要状态，不复制 transcript |
| 正文和版本 | 创作项目 | 发布准备读取指定版本 |
| 可长期复用的新认识 | 主题 | 必须由主管验收后沉淀 |
| 发布效果与经验 | 复盘 | 回流主题与后续选题上下文 |

同一来源只保存一份权威材料；项目级资料包保存该来源对本次调查的用途、解释和限制，不复制来源正文。

## 11. 角色与权限边界

- **主管**：读取跨业务上下文；拟调查提纲；派记者；验收资料包；形成调查后写作方向；经 Owner 确认后派写手。
- **记者**：调查、采集、核验、关联来源、报告冲突与未知；不得保存正文版本，不得决定最终写作方向。
- **写手**：读取已批准方向和资料；完成与修改正文；不得改变选题决策或把未核验内容升级为事实。
- **策划**：提出调查前选题并维护长期主题判断；不执行本稿专项调查，不替写手完成正文。
- **资料员**：整理、归档和维护来源；不决定本稿结论。
- **Owner**：确认调查范围；确认调查后写作方向；保留发布、停止项目和重大范围变化的最终决定。

现有员工工单的单跳原则保留：主管派记者，记者交回主管；主管验收后再单独派写手。不得实现“记者完成后自动触发写手”的隐藏多跳链路。

## 12. 失败、冲突与恢复

### 12.1 资料不足

记者如实提交已覆盖范围与缺口。主管可补查、缩小文章范围或建议停止，不得把 `partial` 显示为完整调查。

### 12.2 来源冲突

资料包并列记录冲突说法、各自出处、时间和可信度依据。主管写作方向必须说明可表达的确定程度，不能静默选取更符合原角度的一方。

### 12.3 原角度被推翻

这是正常成功结果。主管明确呈报推翻原因和可替代方向；Owner 可批准改向或停止。选题前后快照均保留。

### 12.4 Owner 修改提纲

修改生成新版本。尚未开始的记者工单使用新版本；运行中的工单暂停在安全边界，由主管决定继续当前范围、补发新轮次或取消。不得静默替换工单输入。

### 12.5 记者运行失败

保留已经归档的来源和部分资料包，工单标记真实失败或部分完成。主管可针对未完成问题重新派工，不重复采集已确认材料。

### 12.6 写作中发现缺口

正文保持当前版本，项目转入 `needs_more_research`。补查完成并重新确认受影响的写作方向后才能继续，不允许写手私下绕过调查链。

## 13. 用户界面行为

### 13.1 启动

在创作项目中，Owner 可对主管表达“把这篇写完整”。主管不直接派写手，而是打开或生成“调查提纲待确认”状态，并将提纲呈现在项目的“调查”工作面。

### 13.2 审批

提纲审批和调查后方向审批都必须展示：当前版本、具体内容、修改入口、确认、要求修改和停止。确认动作必须说明后果；不能用聊天中的含糊回复伪造审批。

### 13.3 状态投影

- Today：只显示该项目正在待确认、调查中、待定方向或写作中，并提供进入项目入口；
- 选题：显示已立项及调查后的结果标签，不复制资料包；
- 智能体：显示记者/写手工单状态和运行记录；
- 创作：显示完整业务内容并承担审批；
- 资料库：显示来源被哪些项目和主题引用。

### 13.4 不允许的表现

- 调查资料包只存在对话或 transcript；
- 记者完成后自动派写手；
- 用“证据充分度”暗示调查目标是支持原观点；
- 把未知和冲突隐藏在折叠日志里；
- 调查后静默覆盖原选题角度；
- 为调查新增独立一级导航或第二套来源库。

## 14. 验收标准

### 14.1 主流程

1. 已有选题和来源的创作项目收到“把这篇写完整”；
2. 主管生成问题导向、非结论导向的调查提纲；
3. Owner 未确认前不能生成记者工单；
4. Owner 修改并确认后，记者工单引用精确提纲版本和项目；
5. 记者可新增来源，来源进入资料库并关联调查问题；
6. 记者提交包含事实、反例、冲突、未知与未完成项的资料包；
7. 主管验收并形成调查后写作方向；
8. Owner 未确认方向前不能生成写手工单；
9. Owner 确认后写手读取批准方向和资料包，保存新的正文版本；
10. 调查前选题、两次审批、调查资料包、最终方向和正文版本重启后仍可读回。

### 14.2 改向与停止

- 调查发现推翻原角度的材料时，系统允许主管建议新角度或停止；
- 原选题快照不被覆盖；
- Owner 可以停止项目而不制造空正文或伪成功写手工单。

### 14.3 权限与真相

- 记者不能保存正文版本；
- 写手不能改调查审批或选题快照；
- 每个资料包事实能回指来源，待核验项有明确状态；
- 工单完成必须有业务成果读回，不能以 transcript 结束代替；
- `partial`、`needs_user`、`failed` 与成功在项目和智能体页上保持一致。

### 14.4 真实界面验证

使用真实 Electron 覆盖：

- 两次 Owner 审批；
- 记者运行、补查、失败和范围扩展；
- 原角度成立、调整、推翻、停止四类结果；
- 资料库来源关联和重启后持久化；
- 写手只能在方向获批后启动；
- 1100px 最小窗口、双主题、键盘操作、无横向溢出、无 page error。

## 15. 非目标

本范围不包含：

- 自动发布；
- 自动把记者交付串联到写手；
- 为调查建立新的一级导航；
- 新建与资料库平行的来源存储；
- 要求调查得出支持原选题的结论；
- 自动判定来源绝对真伪；
- 无限制自主扩大到另一选题；
- 重做主题、选题、资料库或智能体的全部信息架构。

## 16. 实施边界

后续实施计划必须先审计并复用现有：

- 创作项目与内容版本协议；
- 选题到项目的 lineage；
- 项目来源关联；
- 主题与来源关联；
- 主管派工、记者和写手角色工单；
- TaskGrant / Capability registry；
- 工单业务读回；
- Studio 审批和状态投影模式。

如果现有对象能够表达某项关系，应扩展该对象，不得建立平行协议。新增记者专项调查能力必须保持角色权限收窄、单跳派工和 Owner 审批边界，不得把日常广域扫描伪装成项目专项调查。
