# 智能体角色模型预设分配设计

日期：2026-08-18  
状态：已获 Owner 设计批准并通过书面规格自查，待 Owner 复核

## 1. Problem

WeMediaBuddy 已支持多个安装级模型预设。每个预设拥有独立接口、模型、思考等级、原生搜索开关、上下文限制、输出限制和加密 API Key；但主管/Pi、记者、策划、写手、资料员当前共同读取同一个全局激活预设与全局故障转移链。

这导致三个问题：

1. 无法按角色任务特征选择模型，例如写手使用写作模型、策划使用高推理模型、资料员使用低成本模型。
2. 一个角色的服务故障可能降级到不适合该角色的模型。
3. 任务回执无法区分计划模型、实际模型和角色专属降级过程。

## 2. Decision

新增安装级“智能体角色模型策略”。模型预设继续作为接口、密钥和模型参数的唯一真源；角色策略只保存五个角色各自的有序预设 ID。

已批准的产品选择：

- 绑定层级：按智能体角色绑定，不按单个实例绑定，不支持派工时单次覆盖。
- 角色范围：主管/Pi、记者、策划、写手、资料员全部覆盖。
- 故障转移：每个角色拥有独立降级链。
- 配置范围：整个 WeMediaBuddy 安装统一，工作空间不能覆盖。
- 存储方式：独立角色策略引用既有模型预设，不复制预设或 API Key。

## 3. Goals

1. 用户能为五个角色分别配置首选模型预设及有序备用链。
2. 每个角色只在自己的链内启动和降级。
3. 员工任务派发后冻结模型策略；后续配置变更只影响新任务。
4. 主管/Pi 在当前回复结束后的安全边界应用新策略，不丢失会话。
5. 模型选择、实际使用及降级过程可观察、可审计。
6. 旧安装确定性迁移，升级后行为不突然改变。

## 4. Non-goals

本功能不包括：

- 为同一角色的不同智能体实例分配不同模型；
- 派工时临时覆盖角色模型；
- 按工作空间覆盖角色策略；
- 自动按任务难度、成本或质量动态路由模型；
- 修改模型预设中的 API、密钥或模型能力定义；
- 改变配图专用模型选择；
- 增加新的角色、权限、任务状态或业务旁路。

## 5. Roles

角色集合复用现有唯一角色合同：

```ts
type RoleId =
  | 'desk'
  | 'reporter'
  | 'planner'
  | 'writer'
  | 'librarian';
```

界面名称：

| Role ID | 界面名称 |
|---|---|
| `desk` | 主管 / Pi |
| `reporter` | 记者 |
| `planner` | 策划 |
| `writer` | 写手 |
| `librarian` | 资料员 |

主管与 Pi 共用 `desk` 策略，不引入第二个主管角色。

## 6. Authority and storage

### 6.1 Model preset SSOT

安装级模型预设继续拥有：

- profile ID 与名称；
- Base URL；
- API 协议；
- 模型名；
- 思考等级；
- 原生搜索开关；
- context window 与 max tokens；
- 系统加密 API Key。

角色策略不得复制 API Key，也不得形成第二套模型配置。

### 6.2 Version 2 configuration

安装级模型配置升级为版本 2：

```ts
type RoleModelPolicyStateV2 = {
  version: 2;
  activeId: string | null;
  profiles: StoredProfile[];
  modelPolicyRevision: number;
  roleModelPolicies: Record<RoleId, {
    profileIds: string[];
  }>;
};
```

约束：

1. 五个角色键必须完整存在。
2. 每条链至少包含一个预设。
3. 同一角色链内不得重复 profile ID。
4. 每个 ID 必须指向现存且已配置的 profile。
5. 保存五条策略时只产生一次原子写入和一次 revision 递增。
6. `activeId` 只用于新建配置和手动测试时的默认选择，不决定智能体运行模型。
7. 旧 `fallbackOrder` 在迁移后不再拥有运行时语义，也不保留第二条智能体选择路径。

## 7. Migration

读取版本 1 配置时执行一次确定性迁移：

1. 生成旧链：`activeId` 在前，随后是去重后的 `fallbackOrder`。
2. 将该链完整复制给五个角色。
3. 写入 `version: 2` 与初始 `modelPolicyRevision: 1`。
4. 不修改任何模型预设、API Key、当前工作空间或业务数据。
5. 迁移失败时保留原文件，不写入部分版本 2 状态，并显示配置错误。

迁移后，五个角色首次运行的候选顺序与升级前完全一致。

## 8. Settings experience

配置入口：`设置 → AI 与模型 → 智能体模型分配`。

页面展示五个固定角色卡。每张卡包含：

- 必选的首选预设；
- 可选的多个备用预设；
- 上移、下移、移除操作；
- 预设名称、模型名、接口协议和思考等级摘要；
- 未通过历史连接测试时的非阻塞警告。

页面只有一个“保存智能体模型分配”动作。五条链一起校验并原子保存；任一链无效时全部保持原样，revision 不递增。

智能体列表和任务详情只读显示：

- 计划预设；
- 实际预设；
- 实际模型；
- 策略 revision；
- 降级原因。

智能体列表不提供模型编辑入口，避免与设置页形成两个真源。

界面必须复用 `src/renderer/styles-foundation.css` 中的品牌变量，不修改 foundation 品牌 token。在亮色、暗色主题及 1100×800 最小窗口下，配置动作必须可达且无横向溢出。

## 9. Task policy snapshot

员工任务派发时，把模型策略快照写入既有任务合同：

```ts
type ModelPolicySnapshot = {
  revision: number;
  roleId: RoleId;
  profiles: Array<{
    profileId: string;
    profileName: string;
    baseUrl: string;
    api: PiApiType;
    model: string;
    thinking?: PiThinkingLevel;
    nativeSearch?: boolean;
    contextWindow?: number;
    maxTokens?: number;
  }>;
};
```

规则：

1. 快照保存全部非密钥运行参数和有序候选。
2. API Key 不进入任务、数据库或日志；runtime 启动时按 profile ID 从安装级加密存储读取。
3. 修改角色策略只影响修改后派发的新任务。
4. 已排队与运行中的任务继续使用派发时快照。
5. API Key 轮换不要求重新派工；任务启动时使用该 profile 当前密钥。
6. 若快照引用的 profile 在启动前不可解析，任务进入 `needs_user`，不得悄悄改用其他角色或全局链。

## 10. Desk/Pi safe-boundary behavior

主管/Pi 没有普通员工工单，因此按对话回合冻结：

1. 当前正在生成的回复继续使用启动该回合时的 `desk` 策略。
2. 保存新角色策略不打断当前回复。
3. 下一条用户消息发送前比较 `modelPolicyRevision`。
4. revision 变化时停止旧 runtime，并用新的 `desk` 链启动 runtime。
5. 保留现有会话文件和历史消息，不创建空白会话。
6. 如果新链启动失败，保留用户消息且不自动重复发送；进入可恢复错误状态，等待用户修复后主动重试。

## 11. Runtime resolution

新增统一角色解析入口：

```ts
resolveRolePiConfigChain(roleId, policySnapshot?)
```

行为：

- 有任务快照时严格按快照顺序解析。
- 无任务快照时读取当前安装级角色策略。
- 只返回指定角色的候选，不追加 `activeId`、旧全局链或其他角色候选。
- profile ID 无法解析时返回明确配置错误，不静默跳过。

现有 `startPiRuntimeWithFallback` 和 `runPiPromptWithFallback` 继续负责启动与 prompt 阶段降级，但必须接收角色解析结果；内部不得再次读取全局链。

所有主管和员工 runtime 调用方必须迁移到该入口。配图工作流继续按其明确的图像 profile ID 解析，不进入角色文本模型链。

## 12. Fallback policy

链执行顺序固定：

```text
首选启动或调用失败
→ 记录失败
→ 如果错误可降级，尝试本角色下一个候选
→ 本角色链耗尽后进入真实失败/needs_user
```

允许自动降级的错误：

- 网络连接失败或超时；
- HTTP 429 限流；
- HTTP 5xx 服务端错误；
- 供应商明确返回的暂时不可用错误。

禁止自动降级的错误：

- 鉴权失败；
- 模型不存在；
- 模型或接口配置错误；
- 上下文或输出限制不满足；
- 内容生成后的业务校验失败；
- 工具调用失败；
- 权限、grant、lease 或任务合同错误；
- 用户取消；
- 外部副作用状态不确定。

自动降级只重跑尚未产生外部副作用的当前模型调用。不得借降级重复不可逆操作或把旧结果当作本次成功。

## 13. Events and audit

复用现有 `fallback-try` 与 `fallback` 事件，不创建重复事件协议。事件补充：

```ts
roleId: RoleId;
policyRevision: number;
taskId?: string;
```

任务最终回执或可查询投影必须提供：

- plannedProfileId；
- actualProfileId；
- actualModel；
- roleId；
- policyRevision；
- fallbackFailures。

禁止写入 API Key、完整鉴权头或其他密钥材料。

## 14. Delete and edit protection

1. 被任一当前角色策略或非终态任务策略快照引用的模型预设禁止删除。
2. 删除失败必须列出全部引用角色，并显示引用该预设的非终态任务数量及可定位任务 ID。
3. 用户必须先从所有角色链解除引用，并等待相关任务终态或主动取消这些任务，才能删除预设。
4. 保存角色策略时再次验证引用，防止并发配置变化形成悬空 ID。
5. 解除角色策略引用不会改变已排队或运行任务的冻结快照。
6. 终态任务可永久保留非密钥快照；删除预设不删除历史审计信息。
7. 若外部损坏或旧数据使非终态快照引用不存在的预设，启动时进入 `ROLE_MODEL_PROFILE_MISSING`，不得跨链兜底。

## 15. Error contract

| Code | Meaning | Runtime behavior |
|---|---|---|
| `ROLE_MODEL_POLICY_REQUIRED` | 角色没有合法模型链 | 不启动；员工任务进入 `needs_user` |
| `ROLE_MODEL_PROFILE_MISSING` | 策略或快照引用不存在的预设 | 不跳过、不跨链；进入 `needs_user` |
| `ROLE_MODEL_AUTH_FAILED` | API Key 缺失或鉴权失败 | 不降级；提示修复预设 |
| `ROLE_MODEL_CONFIG_INVALID` | 模型名、协议或限制配置错误 | 不降级；提示修复预设 |
| `ROLE_MODEL_CHAIN_EXHAUSTED` | 所有可降级候选均失败 | 保留完整失败列表；进入 `needs_user` |

员工任务不得因为同项目存在旧内容、旧计划或旧资料而被读回层误判为本次成功。

## 16. Acceptance criteria

1. **迁移**：版本 1 配置升级后，五个角色的候选顺序均与旧全局链完全一致。
2. **迁移原子性**：迁移失败时原文件保持可读，无半写入版本 2。
3. **角色隔离**：五个角色同时派工时，各自只使用自己的模型链。
4. **策略冻结**：任务 A 派发后修改写手链；A 使用旧快照，新任务 B 使用新 revision。
5. **专属降级**：记者首选发生可降级故障时，只尝试记者备用链。
6. **无跨链兜底**：记者链耗尽后不得使用写手、主管或旧全局预设。
7. **禁止错误降级**：鉴权、模型不存在、业务校验、权限和用户取消只执行一次，不切换模型。
8. **全链失败**：员工任务进入 `needs_user`，显示每个候选失败原因，不产生虚假成功回执。
9. **删除保护**：删除被当前策略或非终态任务引用的预设失败，并准确列出全部引用角色及任务。
10. **原子保存**：任一角色链无效时，五条策略均不改变，revision 不递增。
11. **主管安全切换**：保存新 `desk` 策略不打断当前回复；下一条消息使用新链并保留会话。
12. **任务可观察性**：任务详情可读取计划预设、实际预设、实际模型、角色、revision 和降级原因。
13. **密钥边界**：任务快照、日志、事件和回执均不包含 API Key。
14. **配图隔离**：配图专用模型继续使用明确指定的图像预设，不受角色文本模型链影响。
15. **真实界面**：设置页在双主题和 1100×800 下可完成配置，无横向溢出、遮挡或不可达操作。

## 17. Verification strategy

每项验收只保留一个最强证明：

- 配置迁移与原子保存：配置域目标测试。
- 角色解析、冻结和删除保护：角色策略域目标测试。
- 可降级/不可降级分类及无跨链兜底：现有 fallback 运行时目标测试扩展。
- 五角色并行隔离及真实任务终态：员工工单集成测试。
- 主管安全切换与会话保留：Pi dock 集成场景。
- 设置页交互、双主题和 1100×800：聚焦 Electron 场景。
- 密钥边界：持久化与事件载荷断言。

## 18. Scope boundary

允许修改：

- 安装级 Pi 配置结构、迁移与安全解析；
- 角色模型策略 IPC；
- 主管和员工 runtime 的模型链解析；
- 工单策略快照、事件与投影；
- 设置页智能体模型分配界面；
- 智能体/任务详情只读模型信息；
- 直接覆盖上述契约的测试与设计文档。

明确不修改：

- foundation 品牌 token；
- 工作空间、浏览器 profile、账号绑定；
- 角色权限、任务状态机和业务命令授权；
- 配图模型配置；
- 发布流程或外部平台操作；
- 单实例、单次派工或工作空间级模型覆盖。
