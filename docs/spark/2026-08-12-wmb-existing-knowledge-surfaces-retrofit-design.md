# WMB 现有知识前端原位改造规格

状态：上位架构已批准，本规格用于实施设计  
日期：2026-08-12  
范围：现有主题、资料库、关系画布、Pi 和创作界面改造，不授权实现

## 1. 决策

不新增顶层 Wiki 应用。现有知识资产导航保持：

```text
主题 | 资料库 | 关系画布
```

职责升级：

- 主题：Wiki 主阅读面；
- 资料库：Raw、Evidence、Inbox、Ingest 回执、Knowledge Health；
- 关系画布：关系、变化、健康探索；
- Pi：Query、自由记录、本次沉淀；
- 创作：知识实际调用和结果回流。

已退役 `DomainMapView` / `TopicDossierView` 不得复活。`LibraryTopicsView` 是唯一 Topic 前端，Topic 业务身份只有现有 `topics.id`。

## 2. 通用交互原则

1. Wiki 当前综合优先，内部结构按需展开；
2. 所有自动动作完成后显示“改变了什么”，不只显示成功；
3. 页面间使用现有稳定对象 ID 深链；
4. loading 使用骨架，失败显示可重试原因，stale/争议不可隐藏；
5. 自动刷新不抢走当前选择、滚动位置和用户编辑；
6. 用户不填写 Knowledge Note 类型、关系或证据等级；
7. 所有版本恢复明确说明会生成新版本；
8. 键盘、焦点、屏幕阅读器和 reduced motion 完整支持。

## 3. 主题页改造

目标文件：`src/renderer/library-topics-view.tsx` 及既有 topic styles。

### 3.1 主题首页

保留：搜索、状态筛选、列表、主题维护台账入口、workspace 选择记忆。

列表项新增紧凑状态：

- 当前综合一句话；
- 最近知识变化；
- 证据/争议/stale 指示；
- 最近活跃原因；
- 相关内容和结果数量。

不增加营销式统计卡墙。

### 3.2 Topic Wiki 默认详情

详情顺序：

1. **当前认识**：WikiPage 当前版本标题、自足摘要、as-of、适用边界；
2. **最近变化**：最新 KnowledgeUpdateReceipt，新增/强化/限域/冲突；
3. **为什么**：关键证据和反证，来源性质、时效和定位；
4. **对创作的影响**：角度、失效表达、选题、内容、表现、复盘、方法；
5. **待研究**：Question 和 HealthIssue；
6. **完整档案**：现有八类 dossier tabs；
7. **版本**：WikiPageVersion 时间线、差异和恢复。

当前 `judgments/evidence/return` 三段可作为前三层骨架；现有 deep dossier 保留，不默认压过 Wiki 综合。

### 3.3 争议与 stale

- disputed 显示各方主张、证据和未解决原因；
- stale 显示触发知识变化、最后成功版本和“重新编译”状态；
- failed 显示失败原因，不显示半成品正文；
- inference 以语义标签区分，不使用颜色作为唯一信号。

### 3.4 Topic 变化历史

主题维护 proposal snapshot、知识 ChangeSet 和回执统一投影为主题时间线。结构变更和知识内容变更视觉区分：

- 结构：新建、改名、合并、归档、关系迁移；
- 认识：新增、强化、削弱、限域、冲突、替代、恢复。

### 3.5 Today 深链

持续关注条目必须携带真实 topicId，点击打开准确 Topic Wiki。显示 reason 和最新知识变化。移除以空 ID 打开首页的伪深链。

## 4. 资料库改造

目标文件：`src/renderer/library-view.tsx`、parts 和既有 library styles。

### 4.1 导航

现有 `资料 / 重新发现 / 移出` 调整为：

- `资料`
- `待处理`
- `知识健康`
- `移出`

“待处理”复用 rediscovery 三池；“知识健康”读取 KnowledgeHealthIssue。资料列表继续是 Source 唯一管理入口。

### 4.2 资料列表

保留搜索、核验/管理筛选、观察中和分页。新增：

- Raw 正文缓存状态；
- 是否已消化；
- 最近知识变化摘要；
- 关联 Topic；
- 冲突/过期/健康问题指示。

状态应紧凑内联，不增加嵌套卡片。

### 4.3 资料详情

从抽屉行为升级为可深链详情，但保持同一 `LibraryView` 路由。区域：

- 原始来源与正文；
- AI 摘要和来源质量画像；
- Evidence 贡献：支持/反驳/限定哪些固定知识版本；
- 关联 Topic、Entity、内容、发布、复盘和方法；
- 最近 Ingest/重编译回执；
- 用户批注；
- 核验/管理、重新抓取、原文、归档等现有操作。

用户可以纠正和批注，但不直接编辑 EvidenceLink。

### 4.4 待处理

每项显示重现原因、证据变化和建议下一步。动作：

- 打开资料；
- 打开 Topic；
- 让记者补料；
- 进入选题；
- 归档/忽略；
- 添加批注。

动作复用现有角色、页面和业务命令，不新建平行任务系统。

### 4.5 Knowledge Update Receipt

资料保存后使用非模态内联回执，可收起但持久可回看。摘要包含资料去重、知识变化、更新页面、创作影响和未处理项。点击可进入受影响 Topic 或画布变化视图。

### 4.6 知识健康

按严重度和问题类型筛选。每项显示影响对象、依据、建议、自动修复状态和解决记录。确定性修复可以执行；争议问题提供打开证据、补料或接受风险，不提供“强制一致”按钮。

## 5. 关系画布改造

目标文件：`knowledge-canvas-view.tsx`、layout、relations、types 和 styles。

### 5.1 三种视图

- `关系`：当前自由布局和关系编辑；
- `变化`：选择一个 KnowledgeUpdateReceipt/ChangeSet，突出新增、更新、冲突、替代和晋升；
- `健康`：投影孤立、重复、冲突、stale、失效关系和缺页问题。

切换只改变投影与强调，不创建第二份画布数据。

### 5.2 节点

节点增加：当前对象类型、状态、最近变化、核验/争议/stale 标记。点击打开统一详情侧栏，提供跳转正式页面。节点仍只保存引用与布局。

### 5.3 数据刷新

订阅现有 `dataChanged` 扩展 scope，替代 5 秒轮询作为主路径。刷新合并新对象状态但保留当前 selection、viewport、drawer 和未提交连接操作。必要的轮询只能作为恢复兜底。

### 5.4 选中到创作

保留 selected_only 服务端约束。新增明确动作：

- 与 Pi 讨论；
- 生成/更新创作简报；
- 加入现有内容项目；
- 创建选题候选。

必须展示实际传入的对象清单；不允许 UI 显示选中 A、服务端实际使用全画布。

### 5.5 建议

现有 suggestion 确认条继续用于用户主动的画布布局建议；AI 正式知识更新不走该审批队列。需区分“画布建议”和“知识已自动更新”。

## 6. Pi 改造

Pi 回答结束后增加可折叠“知识使用与沉淀”：

- 使用的 Wiki/知识/来源数量及入口；
- 风险：stale、disputed、inference；
- 本次新增、限域、冲突或综合；
- 未写回及原因；
- 回执和差异入口。

用户可在此批注纠正或要求恢复。工具调用原始 JSON 仍按需展开，不与知识回执混为一谈。

## 7. 创作界面改造

复用 Studio 现有 context rail。新增：

- 当前采用的 Topic Wiki 当前版本；
- 用户原则与禁忌；
- Evidence 和来源质量；
- 已验证/失效模式；
- 历史表现与复盘；
- disputed/stale/inference 风险；
- 使用固定版本和使用原因。

知识上下文默认只读。用户通过批注或 Pi 改变知识，不直接在 Studio 修改知识卡。

保存内容版本时记录实际采用的知识版本；只被检索但未进入简报或正文的知识不得标为 used。完成、发布和复盘后展示结果回流回执。

## 8. 全局知识核

不新增顶层入口。主题页 Scope 切换器提供“当前赛道 / 全局知识核”。Global Map 使用同一主题/Wiki 组件，显示通用 Method、Synthesis、用户原则和跨赛道来源。不能把不同 data-root 私有内容泄漏到 Global。

## 9. 删除与收敛

- 删除或迁移已退役 `knowledge-system-view.tsx` 死代码，不再维护第二套领域/主题组件；
- 收敛 `work_carry_items` 持续关注技术债到正式 Topic progress；
- Canvas 固定对象类型在迁移规格中受控扩展；
- dataChanged 增加 knowledge/topics/canvas/health/receipt scopes；
- 旧路由和本地存储键提供一次性兼容迁移后删除。

## 10. 可访问性与响应式

- Topic 正文 65–75ch；
- 争议、状态和关系不只靠颜色；
- tabs、版本时间线、画布 mode 有明确 aria；
- 画布所有主要动作支持键盘；
- 窄屏将右侧 rail 变为同页可关闭面板，不用横向溢出；
- 变化高亮使用 150–250ms 状态过渡，并支持 reduced motion；
- 自动刷新使用 aria-live 简短宣布，不重置焦点。

## 11. 验收

1. 侧栏仍只有主题、资料库、关系画布三个知识入口。
2. Topic 默认首先看到当前综合和最近变化，完整档案仍可深查。
3. 新资料摄取后资料库出现持久回执，Topic 无刷新跳转即可更新。
4. 同一 Topic 只有一个业务身份和一个主前端。
5. 画布能切换关系/变化/健康且不复制对象。
6. 画布自动刷新不丢选择、viewport 或编辑状态。
7. Pi 明确显示本次使用和沉淀，纯复述不伪造更新。
8. Studio 显示实际采用的固定知识版本，风险状态可见。
9. 用户主路径无需填写任何 Knowledge Note、关系或证据表单。
10. stale、failed、disputed 和 inference 均有可观察 UI。
11. 屏幕阅读器和键盘可完成主要浏览、切换、批注和跳转。
12. 已退役平行知识组件和持续关注双轨完成收敛。
