## 1. Backend — work_carry_items & ferment pipeline

### Schema (src/main/db/late-migrations.ts)

  id PK, object_type CHECK(plan_item|source|topic), object_id, fingerprint, title,
  state CHECK(active|watching|done|dismissed|expired), priority, topic_id REFERENCES topics(id),

### src/main/ferment.ts (public surface)
- Types: CarryObjectType='plan_item'|'source'|'topic'; CarryState; AftershockItem; WorkCarryItem (includes storyKey, stage);
  FermentingBundle = { items: WorkCarryItem[]; watchingItems: WorkCarryItem[]; topics: [{topicId,title,activeCount,watchingCount,latestTitle,fermentedDays}]; pinnedSources: [...] }
- Constants: DEFAULT_ACTIVE_DAYS=7, DEFAULT_WATCH_DAYS=14, MAX_FERMENTING=5, topics LIMIT 8
- fingerprintPlanItem({title,topicId,sourceIds}) / fingerprintSource(sourceId) / fingerprintTopic(topicId) — sha256 hex, 32 chars
- classifyTimeliness / TIMELINESS_WINDOW_HOURS {breaking:24, hot:72, evergreen:null} / isMultiDayTimeliness
- dismissCarryForPlanItem (plan_item 否决泊车；无行则插 dismissed 指纹行防复活)
- refreshWorkCarry(planDate) pipeline: expireDueCarryItems → promoteCarryWatchingToLibrary → seedCarryFromRecentPlans → seedCarryFromHighValueSources → seedCarryFromTopics → mergeSimilarCarryItems → refreshAftershocks → backfillCarryStoryKeys → deriveCarryStages → recomputeDecayScores → return listFermentingBundle
- mergeSimilarCarryItems: sameStory (topicId 相等 → shared≥2 或 Jaccard≥0.5 → 标题 bigram≥0.5); keeper=last_seen 最新；被合并行置 dismissed，reason=合并为同一故事:…
- listFermentingBundle(planDate): loadTodayPlanDedup → listCarryItems(active|watching,80) → filter plan_item|source (topic 行被排除!) → compareCarry sort → items = active ∧ !isCoveredByTodayPlan ∧ (stage=='fermenting' 或 hasWhyWatching) slice(0,5); watchingItems = state=='watching' slice(0,5); topics 聚合 SQL (GROUP BY topic_id, activeCount/watchingCount/latestTitle/originPlanDate, LIMIT 8); pinnedSources = listPinnedSources
- setCarryState (revision CAS; watching→14d / active→7d 续期), markCarryDoneForPlanItem (object_id + fingerprint 双路径), upsertCarryFromPlanItem (priority>2 且非多日 → null; 已有 project → null; 尊重 watching/done/dismissed 不复活; state = priority≤1或多日 ? active : watching)
- 私有 seeders: seedCarryFromRecentPlans (近7日 priority≤2 plan_items, LIMIT 40), seedCarryFromHighValueSources (近7日 priority≤1 未入项目 sources, LIMIT 20), seedCarryFromTopics (近7日 topic 聚合 opportunityCount≥2 或 lastPlanDate<今天, LIMIT 12, state='watching', story_key=`topic:${topicId}`)
- refreshAftershocks (余波: 同 topic 新来源 / sameStory plan_item 引用 / 标题 bigram≥0.5), backfillCarryStoryKeys, deriveCarryStages (watching→cooling; active 有余波/未完结→fermenting; else emerging; 幂等), recomputeDecayScores (base 1/0.55 + priorityBoost + aftershockBoost − days*0.12, min 0.05)

## 5. Cutover seam 结论

安全缝 = 只换「读投影」，保留 work_carry_items 作决策层：
1. proposals.ts / getOpportunityPool 直读 work_carry_items(fingerprint+state)，不走 listFermentingBundle → 新 topic-progress 投影不影响台账终态。
2. 新建 topic-progress 投影（替代 listFermentingBundle 的 items/topics 段），FermentingBundle 形状在 4 处声明（ferment.ts / app-types.ts / global.d.ts / editorial-brief.ts），需同步迁移或保留薄适配。
3. FermentingRail 已携带 topics 数据但未渲染 → 前端把 topics 段提为 rail 主体、items 降为辅助即可，不新增 IPC。
4. 刷新入口保留: refreshWorkCarry 管道中 expireDue/promote/dismiss 语义由 proposals 依赖，不得删；seedCarryFromTopics 生成的 topic 行当前不可见（items 过滤排除），M-5001 应决定去留。
5. createFromCarry 仅 plan_item → createProjectFromPlanItem; topic rail 需新增 topic→createContentProjectWithVersion({topicId}) 或 topic→机会 创建路径。

## 6. Risks

- FermentingBundle 类型 4 处重复，整型替换需同步改 getToday/editorial-brief/pi payload
- proposals 台账终态 = carry state 机 (dismissed/expired/done)，若 topic-progress 砍掉 plan_item carry 行则台账/恢复断裂；必须保留指纹态行或迁移到决策表
- seedCarryFromTopics 的 'topic' 行是死重（不渲染不进 items）
- today-creation-actions.test.mjs 源码嗅探 CreateIconButton，rail 按钮改造会碎
- editorial-brief `持续关注：` 行进 Pi 提示词，投影改形状 = 提示词契约变化
- MAX_FERMENTING=5 / topics LIMIT 8 截断语义
- broadcast scopes: carry.refresh/carry.state/carry.dismiss → ['today','proposals']；换投影需保持刷新后 UI 重拉 today:get
