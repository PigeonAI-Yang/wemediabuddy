# WMB-4801 · CAP-025 写路径基线与迁移差距

日期：2026-08-05
证据清单：`.ai/wmb-4801-write-route-manifest.json`（`wmb.write-route-baseline.v1`）

## 结论

WMB-4801 **只封存当前事实**：写入口、进程所有者、profile 路径、legacy read model 与 root data 类别。它不实现 WMB-4802 及之后的 BrowserProfile registry、ActiveWorkspaceRuntime、`CommandEnvelopeV1`、dispatcher、grants、runtime epoch、browser-operation 或 legacy write freeze。

当前系统已有多种局部正确性机制：

- MCP 的 `mcp_request_results(tool, request_id, result_json)`；
- knowledge brief/suggestion 的 request replay、revision 与静态 snapshot；
- X List operation 的 `request_id`、`input_hash`、冻结输入与 item 状态；
- jobs 的 dedupe key、atomic claim 与 snapshot uniqueness；
- UI CRUD 的部分 optimistic revision；
- scheduler generation、frozen context 与 late-result 检查。

这些机制彼此独立，绑定的身份集合也不一致。它们**不等于 CAP-025**：当前没有统一的 `CommandEnvelopeV1`，没有一个 active-root serial dispatcher，没有每次启动的新 runtime epoch，没有把 command ID、normalized input、workspace/runtime/profile/account/object identity 一并纳入的统一 `inputHash`，也没有 task grant、precise execution grant 与原子提交的统一 durable receipt/audit。相同 `request_id` 在部分 MCP 路由甚至只按 tool/request 查旧结果，不能证明“同 request + 同 hash replay、变 hash conflict、stale identity zero write”。

## 当前写路径为何不能被视为授权

1. **root 选择分散**：UI handler 常调用 `loadSelectedDataRoot()`；MCP 使用启动时闭包 `rootPath`；scheduler tick 再取 selected root；Pi 仅继承 MCP URL。它们没有共同的 runtime epoch。
2. **进程所有权不等于业务 authority**：Pi child、browser child、XHS child 能写各自 session/cookies/platform state，不表示它们可以选择 workspace、签发 grant 或确认业务事实。
3. **profile 共享不等于 root 共享**：installation physical X profile 可被多个 root 使用，但 sources、List binding/cache、account snapshot、operations、receipts、content、knowledge 必须保持 root-local。当前正式 registry/binding contract 尚未交付。
4. **operation/job/revision 不等于统一 receipt**：它们未统一覆盖 workspace/runtime/task/grant/profile/account/object identity，也不能给所有 transport 提供一致 replay/conflict/zero-write 语义。
5. **兼容读取不等于兼容写入许可**：CAP-025 采用 replacement migration；历史数据可读，但迁移后旧 capability 的 direct writer 必须消失。
